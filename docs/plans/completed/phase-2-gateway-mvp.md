# Phase 2 — Gateway MVP

Status: Completed (merged in PR #3, 2026-10-06; CI green on master)
Owner: coding agent
Depends on: Phase 0 (complete). Phase 1 is deferred; see Decisions D1.
Spec: `docs/architecture/serverflow-spec.md` §6–9, §23–25, §28–29, §31, §50–51, §58 Phase 2

## Outcome

A Go HTTP gateway (`cmd/gateway`) that serves a minimal OpenAI-compatible API
and streams responses from a single configured upstream (any OpenAI-compatible
server: vLLM later, a test fake now). It assigns a request ID, validates input,
normalizes errors, logs structured JSON, exposes Prometheus metrics, and shuts
down gracefully.

Endpoints (spec §58 Phase 2):

```text
GET  /healthz
GET  /readyz
GET  /metrics
GET  /v1/models
POST /v1/chat/completions   (stream and non-stream)
```

Acceptance target from the spec: gateway overhead (excluding inference)
< 25 ms p95 (§31), measured and recorded.

## Non-Goals

- No scheduler, worker registry, worker agent, or mock worker (Phases 3–5).
- No multi-upstream routing, retries, circuit breakers (Phases 6, 15).
- No authentication, tenants, rate limiting, admission control (Phases 8–9).
- No Redis, Postgres, Kafka, OpenTelemetry (Phases 8–12). No `trace_id` yet.
- No `/v1/completions` (spec lists it as an initial endpoint, but the Phase 2
  bullet omits it; deferred, see D4).
- No real vLLM or GPU. No Docker image build.

## Current Architecture

- `cmd/gateway/main.go` loads config, builds a logger, logs one line, exits.
- `internal/config` (typed config, defaults → YAML → env, `Validate()`), with
  `GatewayConfig{Port}` only. All binaries share one `Config` and `Default()`
  must keep validating for every binary.
- `internal/telemetry` provides `NewLogger` / `NewDefaultLogger` (slog JSON).
- No `pkg/`, `internal/gateway`, `internal/api` yet. `ARCHITECTURE.md` already
  names `internal/gateway` as the gateway home.
- Dependency direction (ARCHITECTURE.md): `cmd/*` → `internal/*` → `pkg/protocol`.

## Decisions (D1, D4, D5, D6, D9 confirmed: option A of each)

- **D1 Phase 1 deferred.** Phase 1 needs an NVIDIA GPU, unavailable locally. The
  gateway is developed against a test-only fake upstream. Phase 1 is deferred
  to a cloud GPU box or Phase 13. This departs from "do not jump ahead"
  (spec §63) and needs explicit approval.
- **D2 Single static upstream.** New config `gateway.upstream_url` and
  `gateway.models`. Replaced by the registry/scheduler in Phases 4–5. Keep the
  upstream call behind a small interface so Phase 5 can swap in the scheduler.
- **D3 Validate, then forward the original body.** Parse and validate into the
  normalized `InferenceRequest` (spec §9), but forward the client's original
  JSON bytes upstream so unknown OpenAI fields are not dropped.
- **D4 `/v1/completions` deferred.**
- **D5 Request IDs are always generated by the gateway** (`req_` + random),
  returned as `X-Request-ID`. Inbound `X-Request-ID` is ignored (spec §6 step 2).
  A single `attempt_id` (`att_…`) is logged per request, preserving the
  attempt model from §7 for Phase 6.
- **D6 `/readyz` = upstream reachable.** Probe the upstream with a short
  timeout (default 1s, cached ~2s) on a configurable path
  (`gateway.readiness_path`, default `/v1/models`, which every OpenAI-compatible
  server serves). `/healthz` is liveness only and never touches the upstream.
- **D7 Upstream non-2xx before streaming starts is passed through** (status and
  body; vLLM already returns OpenAI-shaped errors). Gateway-originated failures
  use the normalized error model.
- **D8 Failure after first token terminates the stream** with an SSE error
  event and no retry (spec §25).
- **D9 One new dependency:** `github.com/prometheus/client_golang`. Routing
  uses the stdlib `http.ServeMux` (Go 1.22+ method patterns); no router
  dependency.

## Implementation Notes (deviations and additions)

- **D9 pinned to `client_golang` v1.23.2**, not latest: v1.24.1 requires Go 1.25
  and silently raised the `go` line in `go.mod` and `go.work`. v1.23.2 keeps
  `go 1.24.0`, matching the documented "Go 1.24+" requirement and CI.
- **Self-review fixes:** per-request body read timeout (a slow client could hold
  a connection forever); readiness probe detached from the caller's
  cancellation (one disconnecting client cached a false "not ready"); a response
  aborted after it began is logged and counted as 502, not the 200 already written.
- **Independent verify and review passes** (two fresh subagents, read-only)
  found, and these are fixed with tests that failed first:
  - **P1 validation bypass.** Go's JSON decoder is case-insensitive and keeps the
    last duplicate; vLLM is exact, and the original body is forwarded. `MODEL`,
    `Max_Tokens`, duplicate keys, and a second token field
    (`max_completion_tokens`) all let a client show the gateway one value and
    the upstream another. Now: strict top-level and per-message key parsing
    (ambiguous bodies get 400) and every token field is checked. See ADR-003.
  - Response-side timeouts: each client write is bounded (30s), and
    `gateway.upstream_idle_timeout` (default 120s) cuts a stalled upstream.
  - Assistant messages with `content: null` plus `tool_calls` are accepted.
  - Upstream redirects are never followed; a 3xx is a 502, and a redirecting
    readiness probe is "not ready".
  - Upstream URLs with credentials, a query, or a fragment are rejected, and
    config errors never echo the URL.
  - A client dropping mid non-stream response is a 499, not a 502.
  - A mid-stream error event no longer corrupts a half-written SSE line.
  - A dial timeout maps to 503 (no upstream), not 504. Echoed model and role
    names are truncated.
  - A second independent verification (after these fixes) confirmed all of the
    above against the real binary and found one more defect, also fixed: the
    idle timer counted time blocked writing to a slow client, so a slow but
    alive client could get a false INFERENCE_FAILED when
    `upstream_idle_timeout` was set below the client write timeout. The idle
    clock now runs only while waiting on the upstream. The legacy `function`
    message role is accepted.
  - The verifier showed my explicit "clear the read deadline" line was
    unnecessary (net/http resets it); it was removed and a regression test kept.
- `/readyz` probe timeout (1s) and cache TTL (2s), and the 30s client write
  timeout, are constants, not config.

## Known Limitations / Follow-ups

- **Other generation amplifiers are not capped:** `n` (number of completions)
  is forwarded unchecked, so `n` times `max_tokens` can exceed the intended
  budget, and an omitted token limit is not capped (next item). Decide with the
  Phase 9 quota design.
- **A request that sets no token limit is not capped** by the gateway; the
  upstream's own default applies. Capping would mean rewriting the body
  (contradicts D3). Decision needed: inject `max_tokens`, require it, or accept.
- `/metrics` is served on the public port. Move it to an internal listener or
  protect it before exposing the gateway (Phase 9 auth / Phase 17).
- Unmatched routes and methods return net/http's plain-text 404/405, not the
  JSON error model.
- A stream that fails after the first chunk is logged with `error_code` but
  counted under the wire status 200; failure metrics arrive with Phase 10.
- TTFT is time to the first streamed chunk, which may be a role-only delta;
  true TTFT needs the real worker (Phase 13).
- `/healthz` and `/readyz` requests are logged at info level on every probe;
  `/readyz` keeps returning 200 while draining on shutdown.
- Upstream non-2xx bodies are passed through raw (D7): a non-JSON error body or
  a missing `Retry-After` is not normalized.
- The default `gateway.upstream_header_timeout` (60s) can 504 a long
  non-streaming completion on vLLM, which sends headers only after generation
  finishes. Raise it if that matters.
- No automated test of the real process and signal path (`cmd/gateway`);
  graceful shutdown is tested at `Serve()` level and was verified manually
  against the built binary by two independent runs.
- The upstream dial timeout is the transport default (30s) and is not
  configurable; it still maps to 503.
- On streaming responses, a first token slower than `upstream_idle_timeout`
  (default 120s, for example a long prefill queue under load) becomes an error
  event. Revisit with real vLLM (Phase 13).
- Case-folding edge cases (for example the long s, U+017F) are not caught by the
  key-ambiguity check. Irrelevant for case-sensitive upstreams like vLLM; it
  would matter only for a case-insensitive upstream.
- `TestGatewayOverhead` is load-sensitive by nature (it failed only under about
  4x CPU oversubscription in verification). Do not run it in a shared or
  overloaded CI lane; it is skipped under `-short`.
- Bad `SERVERFLOW_*` environment values are silently ignored (existing
  convention from Phase 0).
- Not run: real vLLM, Docker, Kubernetes. Phase 1 remains deferred (D1).

## Proposed Design

### Packages

```text
pkg/protocol/        InferenceRequest, Message, ID helpers (public contract; no internal imports)
internal/api/        OpenAI wire types, request validation/normalization, error model
internal/gateway/    Server, handlers, middleware, upstream client, metrics
cmd/gateway/         thin main: config, logger, signal handling, Server.Run
```

### Request flow (non-stream and stream)

1. Middleware: generate `request_id`, set `X-Request-ID`, attach logger with
   `request_id`, start timer, record in-flight gauge.
2. Handler: limit body size (`http.MaxBytesReader`), decode JSON, validate
   (model in configured list, `messages` non-empty with valid roles,
   `max_tokens` within limit, types), normalize to `InferenceRequest`.
3. Upstream call: `http.NewRequestWithContext(r.Context(), …)` with the original
   body. Strip `Authorization` and hop-by-hop headers. Transport sets
   `ResponseHeaderTimeout`; no total timeout on streaming bodies.
4. Response: if `stream`, copy upstream SSE to the client, flushing every chunk
   via `http.ResponseController` (no buffering). Record `accepted`, `upstream
   started`, `first token`, `completed` timestamps. Otherwise copy the JSON body.
5. Client disconnect cancels `r.Context()`, which cancels the upstream request
   (spec §24).
6. Access log line per request: `request_id`, `attempt_id`, `model`, `stream`,
   `status`, `duration_ms`, `ttft_ms`, `error_code`.

### Error model (spec §51, subset for this phase)

OpenAI-shaped body `{"error":{"message","type","code"}}` plus the spec code.

| Code | HTTP | When |
| --- | --- | --- |
| INVALID_REQUEST | 400 | bad JSON, missing/invalid fields, body too large (413) |
| MODEL_NOT_FOUND | 404 | model not in `gateway.models` |
| UPSTREAM_TIMEOUT | 504 | no response headers within timeout |
| WORKER_UNAVAILABLE | 503 | connect refused / upstream down |
| INFERENCE_FAILED | 502 | upstream protocol/transport error |
| INTERNAL_ERROR | 500 | unexpected |

UNAUTHORIZED, RATE_LIMITED, NO_CAPACITY are added in later phases.

### Config additions (`internal/config`)

`gateway.upstream_url`, `gateway.models`, `gateway.readiness_path`,
`gateway.max_request_bytes`,
`gateway.max_tokens_limit`, `gateway.upstream_header_timeout`,
`gateway.shutdown_timeout`. Env: `SERVERFLOW_GATEWAY_*`. `Validate()` checks
URL parse and at least one model. Defaults chosen so every other binary still
validates (upstream `http://localhost:8000`, models `["default"]`).

### Metrics (minimal; full set in Phase 10)

`inference_requests_total{model,status}`, `inference_requests_active`,
`inference_request_duration_seconds`, `inference_ttft_seconds`, plus Go and
process collectors on `/metrics`.

### Lifecycle

`http.Server` with `ReadHeaderTimeout`, no `WriteTimeout` (streaming). On
SIGINT/SIGTERM: stop accepting, `Shutdown` with `gateway.shutdown_timeout`,
let in-flight streams finish.

## Acceptance Criteria

1. `GET /healthz` → 200 always. `GET /readyz` → 200 when the upstream is
   reachable, 503 otherwise.
2. `GET /v1/models` returns the configured models in OpenAI list format.
3. Non-stream `POST /v1/chat/completions` returns the upstream JSON unchanged
   with an `X-Request-ID` header.
4. Stream request: the client receives the first SSE chunk before the upstream
   finishes (proves no buffering); chunks and the final `data: [DONE]` are
   passed through intact.
5. Client disconnect mid-stream cancels the upstream request within 1s.
6. Invalid JSON, missing/empty `messages`, oversize `max_tokens`, oversize body →
   normalized 4xx. Unknown model → 404 `MODEL_NOT_FOUND`.
7. Upstream down → 503, upstream slow to respond → 504, upstream dies
   mid-stream → SSE error event then close; none leak goroutines.
8. Every log line for a request carries `request_id`; `/metrics` shows the four
   gateway metrics updating.
9. SIGTERM lets an in-flight stream finish, then the process exits 0.
10. Overhead: p95 gateway-added latency < 25 ms (non-stream), and TTFT overhead
    recorded for streaming, against a zero-latency fake upstream. Results and
    hardware recorded in `docs/benchmarks/phase-2-gateway-overhead.md`.
11. `gofmt`, `go vet`, `go test ./...`, `go test -race ./...`, `go build ./...`
    and `golangci-lint run ./...` all pass; CI green.

## Risks

- **Streaming flush/buffering:** a missing flush silently breaks SSE. Covered by
  the incremental-delivery test (criterion 4).
- **Goroutine/connection leaks** on cancellation or upstream drop. Covered by
  criteria 5 and 7 with leak checks.
- **Memory:** buffering bodies up to the limit. Bounded by `max_request_bytes`.
- **Header leakage:** `Authorization` must not reach the upstream. Tested.
- **Hardware-dependent overhead numbers:** reported as measured on this Mac
  against a fake upstream, not as a production claim.
- **Scope creep toward the scheduler:** keep the upstream interface minimal.
- **Skipping Phase 1** (D1): the real vLLM behavior is untested until a GPU is
  available. Mitigation: the upstream is a standard OpenAI-compatible HTTP API.
