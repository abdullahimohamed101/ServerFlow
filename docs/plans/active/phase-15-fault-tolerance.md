## Outcome

A failing worker costs clients almost nothing and the cluster says so. A worker that hangs, resets connections or fails every request is taken out of the gateway's routing within seconds, probed carefully and brought back; retries cannot multiply an outage because they draw on a budget; a burst the workers cannot take waits a bounded time in a bounded FIFO queue or is refused fast with an honest `Retry-After`; a worker or a gateway can be drained under load without failed requests. The claim is measured with a chaos benchmark on the Phase 7 harness, before and after, and the plan states in advance what counts as working and what the simulator cannot show.

```text
client ─► gateway ── admission (global cap, per-model FIFO queue, max wait) ── shed: 503 NO_CAPACITY + Retry-After
              │            │
              │            └─ router: registry view ∩ breaker.Admissible ─► scheduler ─► worker slot
              │                         ▲ verdict of every attempt at the retry-decision point (fault / ok / neutral)
              └─ retry only if: nothing sent to client ∧ attempts left ∧ budget ∧ deadline ∧ another worker
                 breaker per worker (closed ⇄ open ⇄ half-open), local to this gateway, lazy, no timers
```

Acceptance headline (spec §58): *chaos benchmark: kill, delay and break workers under load; documented recovery.* `resilience.mode` **ships defaulting to `on`** (D1) and takes effect only in registry mode; `mode: off` is the kill switch. The default is flipped in the **last** pull request (D26), after every part exists, is individually mergeable and has been measured. D25 lists every visible change the default brings.

## Non-Goals

- No latency-aware, weighted or load-estimating scheduling and no change to scheduler strategies or the rotor (Phase 14). No tenant fairness or priority (Phase 22); the one tenant guard in D11 is a cap, not fairness. No autoscaling (19).
- No hedged requests, no retry after the first byte, no transparent stream restart (spec §25), no retry of header or idle timeouts (ADR-012 stays).
- No cluster-wide breaker, queue or budget: each gateway decides alone (N gateways allow N times a budget and may eject different halves of a fleet; accepted). Nothing new in Redis; the control plane is not told about breakers.
- No Kubernetes, load balancer or preStop behaviour (Phase 17-18); only the process contract they will rely on (D15-D16).
- No real network faults (`tc netem`, partitions) and no GPU/vLLM: loopback and mock workers (Risks).
- No change to the Kafka event schema (v1), the Postgres schema or `pkg/protocol` wire types.

## Current Architecture (verified in code at 4b9fd32)

- **Attempts.** `forwardRegistry` (`internal/gateway/attempt.go`) routes, sends, and while nothing was written to the client retries on a different worker up to `gateway.max_attempts` (2). `routeAttempt` (attempt.go:151-169) does three things in one function: `Route` reserves a slot, an `attemptRecord` is appended, `AttemptStarted` fires. The next worker is found before the failed response is dropped. Retryable: connect, reset/EOF before headers, configured statuses (502, 503) **without reading the body** (attempt.go:194-197), an empty first chunk. Not retried: header timeout, stalled first byte, 500, 504, 4xx, anything after the first byte (ADR-012). The cleanup defers are registered after the send loop (debt 1).
- **Router** (`router.go`): cached view, `exclude` list, overlay `max(worker-reported, local)` (router.go:98-106), scheduler (`active >= max_concurrency` excluded, scheduler.go:84), slot reservation under one lock. `Route` returns `*api.Error`, so the `NoWorkerError` counts are lost at the router boundary (router.go:105-119); no memory of past failures beyond one request.
- **Registry** (`internal/registry`): heartbeat-age health (suspect 5 s, unhealthy 10 s, lost 30 s); drain is one-way. The gateway ages heartbeats between refreshes (`snapshotCache.age`) so a silent worker stops being eligible at the suspect threshold.
- **Admission today**: only Phase 8's per-tenant limiter. `admission.max_global_requests` (default 1000) is validated (config.go:74, 135) and used by nothing. "All workers full" is an immediate `503 NO_CAPACITY`, `Retry-After: 1`. Worker queues exist (503 `queue_full`) but the scheduler never fills them.
- **Drain.** Mock worker on SIGTERM: `draining` at once (readiness and new requests 503), waits for in-flight. `cmd/worker-agent` on SIGTERM reports DRAINING then deregisters; **the embedded benchmark cluster never calls `agent.Shutdown`** (it only cancels `Run`, which simulates a crash; embedded.go:263-266, 359). Gateway on SIGTERM: `Shutdown` straight away; `/readyz` stays 200 and is cached for 2 s (readiness.go:11, 32); a second signal exits at once; the existing process test expects exit within 1.5-6 s of a 2 s shutdown timeout (signals_process_test.go:90).
- **Mock worker failure injection** (`internal/mockworker/failure.go`): a seeded rate and one mode fixed at start-up (`error` 500, `unavailable` 503 with code `mock_failure`, `drop`, `midstream`); no runtime control, no added delay, no black hole, no crash/restart. The embedded cluster uses `config.Default()` plus 10 s registry thresholds and no fault hooks.
- **Observer seam** (ADR-016): seven moments; tracing and events embed `NopObserver`; label and span-attribute allow-lists; closed event `failure_class` set. `metrics.go:411-416` routes only `RejectCapacity/Model/Internal` into scheduler series. The overhead histogram observes `SinceRequestStart` at the first dispatch (metrics.go:446) and `ServerFlowGatewayOverheadHigh` alerts above 25 ms p95 (alerts.yml:29).
- **Config**: one file per feature under `internal/config`, validator from `Config.Validate()`, env overlay in `load.go` (invalid values ignored), defaults in `Default()`.

## Decisions (confirm before implementation)

- **D1 Switch, scope, configuration.** `resilience.mode: on | off`, **final default on** (user decision), set in the last PR (D26); until then the code default is `off`. Takes effect only when `gateway.worker_source` is `registry`; in static mode it is a no-op and never fails validation (`mode: on` + static starts and serves; there is no "refusing to start" test). `mode: off` / `SERVERFLOW_RESILIENCE_MODE=off` is the kill switch. New `internal/config/resilience.go` (sub-structs `Breaker`, `Retry`, `Queue`, `Drain`), env overlay `SERVERFLOW_RESILIENCE_*`; the mode value is always checked, other settings only when the feature is effective. No secrets. Keys:

  | Key | Default | Bounds |
  | --- | --- | --- |
  | `breaker.consecutive_failures` | 5 | 1-1000 |
  | `breaker.failure_ratio` / `breaker.min_volume` | 0.5 / 10 | 0-1 / 1-100000 |
  | `breaker.window` | 10s | 1s-10m |
  | `breaker.cool_down` / `breaker.max_cool_down` | **10s** / 2m | 100ms-1h (the floor is for tests), ≥ cool_down |
  | `breaker.probe_concurrency` / `breaker.probe_successes` | 1 / 1 | 1-16 / 1-16 |
  | `breaker.probe_header_timeout` | 10s | 100ms-header timeout |
  | `breaker.max_open_fraction` | 0.5 | 0-1 |
  | `retry.budget_ratio` / `retry.budget_min` / `retry.budget_window` | 0.2 / 10 / 10s | 0-1 / 0-1000 / 1s-10m |
  | `retry.first_byte_deadline` / `retry.min_remaining` | 0 (= `upstream_header_timeout` + `upstream_idle_timeout`) / 1s | 0 or ≥ `upstream_header_timeout` / 0-1m |
  | `queue.max_model_depth` / `queue.max_wait` | 128 / 3s | 0-100000 (0 = no queue) / 100ms-60s |
  | `queue.max_tenant_share` | 0.5 | 0-1 (0 = off; authenticated tenants only) |
  | `drain.readiness_grace` | 5s | 0-5m, < `gateway.shutdown_timeout` |

  The trip rule follows the spec's example ("5 failures within 10 s -> OPEN"); the 10 s initial cool-down is a user-delegated decision (D8). Cross-checks: `queue.max_wait` ≤ the effective first-byte deadline; an explicit `first_byte_deadline` below `upstream_header_timeout` is refused (it would silently 504 requests the old gateway served, notably vLLM users who raise the header timeout). The global cap reuses `admission.max_global_requests`.
- **D2 Panic-safe attempts (debt 1), unconditional.** `routeAttempt` splits into `reserve` (Route; no observers) and `startAttempt` (record, `AttemptStarted`), and releases the slot itself if anything after `Route` panics. One deferred cleanup is installed right after the first attempt starts; it keeps **both** the current and the next run reachable (assign `run = next` before ending the old one through a local) so a panic during `abandonAttempt` cannot leak the next slot. It releases the slot, stops the idle timer, cancels, returns any breaker ticket and emits `AttemptEnded(failed, class=panic)` exactly once (an `ended` flag). The panic still propagates to `withRequest`. Contract: *every `AttemptStarted` is followed by exactly one `AttemptEnded`, including on panic and never for an attempt that was not started.*
- **D3 Model pre-check before the limiter (debt 2), unconditional.** In registry mode, before `admit`, `snapshotCache.Serves(model)` (no copy; true when any worker, eligible or not, serves it). Unknown model: `RequestAdmitted`, `RequestRejected(model)`, 404, **no quota, token or lease taken**. No usable snapshot: fall through to the limiter as today. A model whose workers are all LOST is "served" (503 later, charged as today); a model that vanishes between check and routing 404s after the charge (rare).
- **D4 Failure taxonomy and the 503 peek.** Each attempt ends *ok*, *fault* or *neutral*. Retry eligibility is unchanged from ADR-012.

  | Event | Retried | Breaker | Note |
  | --- | --- | --- | --- |
  | connect error, dial refused/timeout; reset/EOF before headers; empty first chunk | yes | fault | |
  | 502 / configured retry status; 503 with an unknown or missing error code | yes | fault | |
  | 503 with code `queue_full`, `draining` or `not_ready` | yes | **neutral** | load or lifecycle, not a fault |
  | header timeout; stall before first byte; 504 | **no** | fault | duplicate GPU work stays refused |
  | stream aborted after the first byte | no | fault, recorded without a ticket | client already got bytes |
  | 500 and other unlisted 5xx | no | **ratio rule only** (never the consecutive rule) | an always-500 worker is otherwise invisible; one poison request across N workers stays below `min_volume`/ratio |
  | 2xx complete; 4xx relayed | no | ok / neutral | |
  | client disconnect; request deadline expiry; `panic` | no | neutral | |

  The mock's injected `unavailable` carries code `mock_failure` and is therefore a fault by design; do not "fix" the mock.
  *The peek.* To tell 503 causes apart the gateway reads at most 1 KiB of a *held retryable* 503 body, **bounded to `min(250 ms, remaining deadline)`**; a timed-out or short read counts as *fault and retryable*; the peeked bytes are put back in front of the body if the response is relayed (as `sendAttempt` does for a 200); the peek is **skipped when no retry is possible** (attempts exhausted, budget/deadline denied), so a terminal 503 is relayed unread as today. The body is never logged or used as a label. A worker can lie to dodge the breaker (trust boundary, Risks).
- **D5 Retry policy upgrades.** `gateway.max_attempts` stays the per-request cap (2). Per-model **retry budget**: a retry is allowed while retries in the window < `max(budget_min, budget_ratio × first attempts)`, where *first attempts* are **routed attempts with Number 1** (not admitted requests, so a shed storm cannot inflate it), in 1 s buckets, keyed by the registry-confirmed model with the same cap as other model labels (overflow models share one `other` budget). **Order (fixes a phantom-attempt defect):** budget and `retry.min_remaining` are checked **before** the retry's `routeAttempt`; the budget is *reserved* atomically at the check and **refunded** if no other worker is found, so only a retry whose send begins stays consumed; a denial (`budget` or `deadline`) or a missing worker relays the held response and sets `RetryDenied`/`NextRouteResult` on the first attempt's `AttemptEnd`; no `AttemptStarted` is ever fired for a retry that does not send. No backoff (a retry goes to a different worker; revisit if `max_attempts` > 2 is used). With `max_attempts: 1` faults and the taxonomy are still recorded, no retry happens, the queue still applies. At low traffic the minimum dominates (up to 100% retries below ~50 requests per window) and a 1 s burst keeps allowing retries for the window; both accepted and documented. N gateways allow N times the budget; accepted.
- **D6 Deadline.** `retry.first_byte_deadline` bounds the retryable phase only (queue wait plus all attempts until the first byte reaches the client), a context deadline on the request-scoped part of each attempt. Default 0 = `upstream_header_timeout` + `upstream_idle_timeout` (one attempt is never cut shorter than today). Expiry before any byte: 504 `UPSTREAM_TIMEOUT`; it does not apply after the first byte. Client cancellation already reaches the worker (spec §24) and is unchanged. No deadline header to workers.
- **D7 Breaker model.** One breaker per worker, local to each gateway, keyed by worker ID and the snapshot's `RegisteredAt` (a re-registration starts closed). Counts *fault*/*ok* (D4). Trips on (a) `consecutive_failures` faults in a row, the first no older than `window`, or (b) ≥ `min_volume` outcomes in the sliding `window` with fault ratio ≥ `failure_ratio` (unlisted 5xx count here only). Never on latency. **The verdict and the probe ticket are taken at the retry-decision point** (headers plus first byte, where `sendAttempt` returns): *ok* once a first byte arrived, *fault* on the D4 fault rows, *neutral* otherwise. A later mid-stream abort is recorded as a fault on the breaker (closed or not) with no ticket, so a worker that streams 60 s then aborts still trips. Breakers of workers missing from the snapshot are pruned on refresh. The cool-down level resets only after a close that has lasted `max_cool_down`, so a worker that passes a probe and re-trips keeps its grown cool-down.
- **D8 States, cool-down, probes (user delegated: 10 s).** CLOSED → OPEN on trip; OPEN → HALF_OPEN lazily when `cool_down` (±20% jitter, injected source) has elapsed, evaluated on `Admissible`/`Acquire` with an injected clock, no timers or goroutines. HALF_OPEN admits ≤ `probe_concurrency` real requests; `probe_successes` ok verdicts close it; a fault reopens it with the cool-down doubled up to `max_cool_down` (10, 20, 40, 80 s, 2 m); a neutral verdict returns the ticket. Probes are live requests (a worker whose readiness answers but inference fails is the case to catch); an attempt that is a probe has `AttemptStart.Probe = true`. *Probe costs, stated:* a probe that ends in a header timeout or stall is not retried (D4), so it costs one client a 504 after the **probe header timeout** (`breaker.probe_header_timeout`, default 10 s, never above the gateway's); with doubling cool-downs this is bounded (acceptance 19 reads "except one per probe"). *Lost tickets:* tickets are returned at the retry-decision point and in the D2 cleanup; as a backstop a ticket outstanding longer than `max(2 × cool_down, upstream_header_timeout + 5 s)` is released. *Why 10 s, and no sensitivity table:* for an always-failing worker the closed form is failed probes per minute ≈ 60 / cool_down (fewer with doubling) and recovery after the fault ends ≈ cool_down + jitter, so shorter cool-downs trade more failed probes for faster recovery by arithmetic, not by measurement; a table of runs would reproduce the formula. Reference points: Envoy outlier detection 5 consecutive 5xx, 30 s base ejection growing with the ejection count; Resilience4j `waitDurationInOpenState` 60 s; Hystrix 5 s. 10 s is safe because failed probes double the wait, only one probe runs at a time, jitter spreads gateways, `min_volume` guards the ratio trip and the ejection cap bounds a false open. The default is 10 s; it changes only on a concrete operational finding recorded in ADR-020.
- **D9 Ejection cap.** Denominator = workers that are **registry-eligible in the current (aged) view**; numerator = breakers OPEN **or HALF_OPEN** among them; at most `floor(max_open_fraction × eligible)` may be open. Workers that are UNHEALTHY, LOST, DRAINING or suspect are outside both counts. A breaker whose trip is suppressed keeps its window and streak and trips on its next outcome once room exists (`breaker_trips_suppressed_total`). With fraction 0.5: 1 eligible worker → 0 open (a single-worker model never opens), 2 → 1, 3 → 1, 4 → 2. This differs from Envoy's 10% (with at least one host always ejectable) on purpose: fleets here are small; 10% would never eject in a three-worker model, and "always at least one" would eject the sole worker of a one-worker model, turning a slow failure into no service. With fraction 1 and all open, routing returns `NO_CAPACITY` fast with `Retry-After` = time to the earliest half-open, 1-30 s. `router.Probe` (`/readyz`) ignores breakers.
- **D10 Eligibility integration.** `Route` returns a typed routing result (carrying the `NoWorkerError` counts) instead of a bare `*api.Error`. After `View()` and the exclusion list and before the scheduler, workers that are not `Admissible` are marked ineligible in the copy (so `eligible_workers` stays truthful). The chosen worker then calls `Acquire` (probe ticket if half-open); a lost ticket race **re-selects inside `Route`**, before any observer fires, at most once per candidate. The registry stays authoritative: breakers only remove workers. The control plane and `/v1/workers` are unchanged.
- **D11 Admission queue, hand-off and shedding.**
  - *Where.* A request waits only when its **first** routing finds the model served and every eligible worker full (`AtCapacity > 0 && Eligible == AtCapacity`, from the typed result). No eligible worker, an unknown model or a stale view is an immediate 503/404; a retry's routing never waits. The queue key is the registry-confirmed model; a model beyond `metrics.max_models` gets **no queue** (immediate 503), so overflow models cannot share a queue and block each other, and client text never creates one.
  - *Strict FIFO with hand-off.* Per model, depth ≤ `queue.max_model_depth`, each waiter ≤ `queue.max_wait` and ≤ the remaining deadline. An arrival **must enqueue** whenever its model's queue is non-empty (no bypass). When a slot on worker W is released, the head waiter receives it **directly under `router.mu`** (`inflight[W]` stays incremented; the waiter gets the `routed` for W without re-running the scheduler), provided W is still eligible in the current view and its breaker admissible; otherwise the slot is released normally and the head waiter re-routes. A release that finds no waiter for that model behaves as today. On every registry refresh, up to `min(waiters, free slots)` head waiters re-route through the normal path (this is when stale counts correct themselves). A waiter that finds its worker's breaker open re-routes, and re-queues at the head if still full. Why not "wake and re-route on release" (the first draft): the overlay is `max(reported, local)`, so after a release the stale reported count still says full and the woken waiter deterministically fails; hand-off is correct and removes the wake race and the arrival bypass (simulated by the reviewer: 8 lost wakes and 16 queue-jumpers in 1307 requests with the draft policy, none with hand-off).
  - *Global cap.* `admission.max_global_requests` counts requests inside the chat handler from just after authentication (body read included) until completion, queued plus running, on this gateway; it is **not** `inference_requests_active` (which starts before authentication; both are documented). Over the cap, new arrivals are refused at once.
  - *Tenant guard.* With authentication, one tenant may hold at most `queue.max_tenant_share` (0.5) of a model's queue depth (`queue_full` beyond it). This stops one tenant filling the queue; it is not fairness (Phase 22).
  - *Shedding order,* all `503 NO_CAPACITY` (**429 stays reserved for the tenant's own quota**, `RATE_LIMITED`): (1) a client that left is dropped silently (499, not shed); (2) global cap → refuse the arrival (`global_limit`); (3) model queue full or tenant share → refuse (`queue_full`); (4) waiter past `max_wait` → `queue_timeout`, oldest first; (5) gateway draining and a waiter that cannot finish within the shutdown budget → `draining`. Running requests and retries are never shed. **`Retry-After` per reason:** `queue_full`/`queue_timeout` = EWMA of recent queue waits rounded up and clamped 1-10 s (1 with no data); `global_limit` = 1 s; `draining` = 1 s; all-breakers-open = earliest half-open, 1-30 s.
  - *Why 503 and not 429 or 529 (research).* RFC 9110 §15.6.4: 503 is the server unable to handle the request because of overload or maintenance, `Retry-After` the estimated recovery; §15.5.30 / RFC 6585: 429 is a *user* sending too many requests, which is Phase 8. OpenAI's error documentation uses 503 ("engine currently overloaded") for capacity and 429 for account limits, but developers report 429 with overload bodies, making 429 ambiguous for clients; Anthropic uses the non-standard 529. Decision: `503` with the existing `NO_CAPACITY` plus `Retry-After`; clients distinguish by status and body code; no 529. The OpenAI-shaped body (`error.message/type/code` plus existing `model` and `eligible_workers`) is unchanged and pinned by a test; the message text carries the reason.
  - *Order with Phase 8.* Cheap pre-limiter checks (global cap, model queue already full, tenant share) run before `admit`, so those refusals spend no quota; `queue_timeout` happens after the charge and is **not refunded** (Phase 8 has no refunds). A queued request holds its concurrency lease. Tail drop is tenant-blind apart from the guard above (D25, Risks).
- **D12 Other queues.** `max_worker_queue` stays the worker's own bounded queue (neutral 503); `max_tenant_concurrency` is Phase 8. Nothing else queues; every new queue is bounded by construction.
- **D13 Observer seam additions (ADR-020 amends ADR-016; `docs/development/observers.md` updated).**
  - `AttemptEnd`: `NextRouteResult` (`""`, `no_capacity`, `worker_unavailable`, `error`) and `RetryDenied` (`""`, `budget`, `deadline`). `NextRouteResult` feeds `scheduler_decisions_total` / `scheduler_no_capacity_total` (debt 3, unconditional).
  - `AttemptStart`: `Probe bool` and `QueueWait time.Duration` (so the overhead histogram can exclude the wait).
  - `Rejection` kind `overload`, reasons `global_limit`, `queue_full`, `queue_timeout`, `draining`. It feeds `admission_rejections_total` and **not** `scheduler_decisions_total` (metrics.go:411-416 must not route it into `schedulingRefused`).
  - New method `QueueWaited(ctx, QueueWait{RequestID, Model, Waited, Result})` (`served`, `timeout`, `client_gone`, `drained`), fired once for a request that actually waited. A request that waits and is shed fires exactly the pair `QueueWaited(timeout)` then `RequestRejected(overload, queue_timeout)`; served: `QueueWaited(served)` then `AttemptStarted`. A request that did not wait fires none.
  - New method `BreakerTransition(ctx, BreakerChange{WorkerID, Model, To, Reason, Failures, CoolDown})` (background ctx). `NopObserver` supplies defaults; tracing and events compile unchanged. The methods and fields exist from PR A as stubs and are never called until the feature that fires them lands.
- **D14 Metrics, spans, events, logs.** Series register when the feature is effective (on and registry); with `mode: off` or static mode `/metrics` is byte-identical to master and the golden series files (which pin names, labels, buckets, not values) are **unchanged**; the registry-mode golden gets deliberate additions in the PR that adds them. Existing allow-listed label names only.
  - Event instruments: `circuit_breaker_transitions_total{model,state}`, `circuit_breaker_probes_total{model,result}`, `retries_denied_total{model,reason}`, `admission_rejections_total{model,reason}`, `inference_queue_duration_seconds{model}` (histogram; requests that waited), `breaker_trips_suppressed_total{model}`.
  - **The overhead histogram excludes queue wait** (`SinceRequestStart - QueueWait`), so `ServerFlowGatewayOverheadHigh` keeps its meaning and queueing does not page; the wait has its own series above.
  - Collectors (read at scrape): `circuit_breaker_state{worker_id,model}` for **non-closed breakers only** (1 = half-open, 2 = open; a closed breaker has no series), `circuit_breakers_open{model}`, `admission_queue_depth{model}`, `gateway_draining`. Per-worker series are bounded by the registered workers (≤ `control_plane.max_workers`) and by the non-closed filter.
  - The metrics observer keeps 0 allocs/op in the steady state for the request-path methods (pre-resolved children like `modelInst`); `BreakerTransition` is off the request path and may allocate.
  - Logs: one line per breaker transition (WARN on open, INFO otherwise; at most one per worker per cool-down), one per shed (INFO, rate-limited to 1/s per reason with a suppressed count), retry denial at DEBUG; never a body, prompt, key or worker error text.
  - Spans: `queue.wait` and `retry.denied` span events; attributes `serverflow.queue.wait_ms` (named to avoid the existing worker-side `queue_ms`), `serverflow.queue.result`, `serverflow.breaker.probe` added to `AllowedKeys`.
  - Events (Kafka): schema v1 unchanged; a shed is a `failed` event with `failure_class=no_capacity` (the reason lives in metrics and logs only); `panic` fits the attempt-level class.
  - Dashboards and rules (D23, D24): one "Resilience" dashboard; alerts `ServerFlowCircuitOpen` and `ServerFlowShedding` (warning) with promtool tests.
- **D15 Worker drain.** *Announce, then refuse, then finish.* The mock gains `--drain-announce` (default 0, today's behaviour): on SIGTERM it reports `draining` but keeps serving for the announce period (set above heartbeat plus registry refresh in clusters and chaos runs), then refuses, then finishes in-flight up to `--drain-timeout`. The agent is unchanged. **`embedded.Cluster` gains `DrainWorker(id)`**, which signals the mock *and* calls `agent.Shutdown` (the embedded cluster otherwise never drains an agent). A drain beyond its timeout still cuts in-flight requests. Real preStop is Phase 17.
- **D16 Gateway drain.** When the feature is effective, on the first SIGTERM/SIGINT: (1) the drain flag is set, `/readyz` returns 503 **bypassing the 2 s readiness cache**, `gateway_draining` is 1; (2) for `drain.readiness_grace` (5 s) the listener stays open and requests are served, responses carry `Connection: close`; (3) at the end of the grace **new requests stop being enqueued** (they route or are refused), existing waiters finish or time out (`max_wait` bounds them) and `Shutdown` starts at once (it waits for in-flight, which includes waiters); waiters that cannot finish inside the remaining shutdown budget get `draining` sheds; (4) a second signal exits immediately (default disposition restored after the first, cmd/gateway/main.go:50), dropping the queue silently; acceptable and documented. The existing process test and the embedded cluster set `drain.readiness_grace: 0` (otherwise they gain 5 s each). With `mode: off` or static mode nothing changes.
- **D17 Mock-worker runtime faults.** New `mockworker.Faults` (atomic settings read by `handleChat`): `SetErrorRate(rate, mode)`, `SetExtraDelay(d)` (before response headers; the 5 s slow worker), `SetBlackhole(bool)` (accept and read, never answer; `/stats` keeps answering so the agent says READY and the breaker is the only detector), `Crash()` / `Restart()` (close listener and connections with a reset; listen again on the same port). Zero value = no fault. No `SetUnready` (flapping health is a registry-level behaviour: a `starting` status makes the agent report LOADING_MODEL, an illegal transition from READY, so it re-registers and the breaker resets on every flap; it is not a breaker scenario and is dropped). No admin HTTP endpoint; process-level chaos uses SIGKILL/SIGSTOP/SIGCONT. The handle exposes counters of "requests the fault touched" as evidence.
- **D18 Chaos harness and scenarios.** `cmd/benchmark chaos --scenario <name>` on the Phase 7 packages: `internal/bench/chaos` (scenarios, windows), `embedded.Cluster` exposes `Faults(id)`, `DrainWorker(id)`, the gateway metrics gatherer and `Config.GatewayMutate func(*config.Config)`; embedded chaos clusters set a short header timeout where noted, `drain.readiness_grace: 0`, and a low `cool_down` floor (100 ms) with scenario-scaled values so `-race -count=10` stays short (the breaker already takes an injected clock for unit tests). Windows: *baseline*, *fault*, *recovery*. Scenarios, and what each can honestly show in the embedded cluster:
  - `worker-crash`: the agent reports FAILED within one heartbeat and the registry drops the worker within a refresh, so the breaker is **not** the detector; this scenario shows registry-plus-retry behaviour and that nothing regresses (Phase 6 already showed 0 failures for a kill). The breaker is made visible only with `worker-freeze`/`error-burst`.
  - `worker-freeze` (blackhole): the breaker is the only detector, and each fault takes the header timeout, so the chaos config **lowers `upstream_header_timeout` to 2 s**; the isolation bound is "header timeout × the faults needed (concurrent), plus a refresh", reported against the spec's 10 s, not against an unreachable 30 s.
  - `slow-worker`: 5 s extra delay run with the header timeout above it (must **not** open a breaker: the false-positive check) and below it (timeouts → faults).
  - `error-burst` with `unavailable` (code `mock_failure`, a fault) at 100% and at a partial rate; and with `error` (500) under D4 (visible only through the ratio rule).
  - `midstream`, `conn-reset` (`drop`), `drain-roll` (D15, one worker at a time, announce above heartbeat plus refresh), `overload` (clients above surviving slots; exercises queue and shedding).
  Results are additive to `result.json` (`chaos`: per-window summaries, one-second series, fault-applied evidence, resilience `on`/`off`/`absent`). **Redis and Kafka scenarios are not duplicated** (Phases 8 and 12 already test them); one assertion is kept: `RATE_LIMIT_UNAVAILABLE` never touches a breaker or the budget.
- **D19 What "works" means (no numbers invented).** Relative to a measured baseline with the Phase 7 3-repeat spread rule; absolute bounds only from configuration or the spec. **Two primary measures per scenario are pre-registered** — success rate in the fault window, and attempts per request — everything else is descriptive (roughly one disjoint range in ten arises by chance per metric). Descriptive measures: time to isolate (fault start to the first one-second bucket after which the faulty worker gets no non-probe first attempts, from `scheduler_selections_total` deltas with `AttemptStart.Probe`/`circuit_breaker_probes_total` separating probes; spec bound < 10 s for freeze/crash given the lowered header timeout); time to recover (fault end, or fault start for permanent faults, until 5 consecutive one-second buckets with ≥ 5 requests have a success ratio ≥ the baseline ratio **ignoring failures that are probes**, which the harness can identify from the probe counter); tail latency of successes (p95/p99 against baseline); latency of failures. Hard bounds: queue depth ≤ `max_model_depth`, queue wait ≤ `max_wait` plus a stated test tolerance, goroutines and memory back to baseline, `scheduler_ineligible_selections_total` = 0. **Validity gate (chaos):** the baseline window exceeds `--max-error-rate`; the fault is not evidenced (D17 counters or the control plane); closed-loop clients exceed `SafeSlotFraction` of the **surviving slots**, defined as registry slots of eligible workers minus the faulted worker's slots (so a frozen but still-READY worker is not counted; `overload` inverts the check); fewer than the minimum requests in a window; the cluster did not settle (`waitReady` returned and five registry refreshes passed); the harness fell behind (open loop); the working tree is dirty or the commit unrecorded; **the machine slept or its clock stepped** (a monotonic-versus-wall offset sampled each tick moves by more than 250 ms; the Phase 8 lesson). Invalid runs are listed and never compared.
- **D20 Before/after.** Baseline = **master's gateway under the same harness**: PR B touches no gateway code and compiles on master, where `config.ResilienceConfig` does not exist, so on master `--resilience` is a **no-op** and result metadata records `resilience: absent` (never `off`). "After" = the branch with `resilience.mode` on; a third group with `mode: off` must agree with the baseline within spread (a behavioural check). 3 repeats per group, same seed and flags, Mac awake (`caffeinate`), no other load. Reported per scenario: min-median-max and the `SPREAD` verdict; an effect is claimed only when ranges do not overlap, otherwise "no distinguishable difference". Phase 7/6/10 baselines were taken without resilience; reproduce them with `mode: off`. `compare` warns when two groups differ in `resilience`.
- **D21 Run A reproduction (debt 5).** One group on the Phase 10 Run A configuration (worker concurrency 4, 12 clients, least-active) against master, `mode: off` (reproduces Phase 10) and the default (on, with hand-off). No target asserted; if the run is still invalid (>5% errors) the note says so and hands the estimator to Phase 14.

- **D23 Silent-agent detection (debt 6; `observability/` changes approved).** Defined as "the gateway stops routing to a worker whose agent went silent" (suspect 5 s + refresh, already in code), measured as time to isolate with the backend frozen. ## Proposed Design

**Package `internal/resilience`** (new; stdlib plus config types; no gateway import; fake clock and jitter injected): `Breaker`/`Breakers` (`Admissible`, `Acquire`, `Record`, `Prune`), `Budget`, `Queue` (per-model FIFO, `Enqueue`, `Handoff`, `Wake`, `Remove`), `Admission` (global and tenant counters). No goroutines of its own.

**Gateway changes** (`internal/gateway`): `resilience.go` (option, wiring, drain state), `attempt.go` (single cleanup, budget/deadline before the retry's routing, verdicts, peek), `router.go` (typed result, breaker filter, tickets, hand-off under `mu`), `snapshot.go` (`Serves`, refresh hook, prune), `handlers.go` (pre-limiter checks, queue wait), `readiness.go` (drain bypass), `observer*.go`, `metrics.go`, `server.go` (drain sequence), `ratelimit.go` (order).

**Request flow** (registry, feature effective): parse → model allowed → *model served?* (D3) → *global/queue/tenant pre-check* (D11) → rate limit (unchanged) → route (view ∩ breakers); if all eligible workers are full, wait in the model queue (hand-off) → send → classify, verdict at the retry-decision point → on a retryable result: *budget and deadline check*, then next worker (excluding tried), send, relay.

**Chaos tests vs harness runs.** `tests/chaos` holds deterministic assertion tests (breaker opens, probes, closes; no retry after the first byte; queue bounds; drain without failures) using `Faults`, polling with generous bounds and cool-downs shortened by config. `benchmark chaos` produces the numbers by hand (nightly, not gated). `make chaos-worker-kill`, `chaos-worker-delay`, `chaos-network-loss` (spec §36 names) wrap `worker-crash`, `slow-worker` and `conn-reset`+`worker-freeze`; network loss is not packet loss.

## Acceptance Criteria

Bracketed letters name the PR that must satisfy the criterion.

1. **[A] Panic safety (D2).** A panic injected in the `RequestRecorder` before the first attempt, in `sendAttempt`, in the recorder after a retry's routing, in `abandonAttempt`, and in an observer: in-flight returns to 0 on every worker (both runs' slots), `AttemptEnded(failed, class=panic)` fires exactly once per started attempt and never for an unstarted one, the client gets a 500 or an aborted connection, `RequestCompleted` fires once. Fails on master (shown first).
2. **[A] Model pre-check (D3).** With a limiter, an unknown model returns 404 and the tenant's request, token and concurrency counters are unchanged; a known model is charged as before; no usable snapshot still reaches the limiter; a model with only LOST workers is "served"; sequence `Started, Admitted, Rejected(model), Completed`.
3. **[A] Second-routing metric (debt 3).** A retry whose second routing fails increments `scheduler_decisions_total` and `scheduler_no_capacity_total` once with the right result and reason, and nothing else changes.
4. **[A][G] Off means off; default-on differs only as documented.** (a) Static mode and `mode: off`: a table-driven differential test in `internal/gateway` against recorded master outputs (status, body, headers minus IDs/dates, normalized logs, `/metrics` series names) is identical apart from the three fixes; the golden series files are unchanged. (b) Default on, registry mode: differences only in D25 items 1-4, 7, 8, 11 (each asserted by a named test), and a fault-free run with free capacity is identical to master apart from the new series. (c) `mode: on` with static mode starts, validates and serves.
5. **[D] Taxonomy (D4).** Table-driven over every row, including 503 with each of `queue_full`, `draining`, `not_ready`, an unknown code, a 1 MiB body, binary, malformed JSON, no body, and a body that stalls: the peek never exceeds 250 ms or 1 KiB, a timed-out peek is a retryable fault, peeked bytes reach the client intact when relayed, a terminal 503 (no retry possible) is relayed without a peek, unlisted 5xx counts in the ratio rule only.
6. **[D] No retry after the first byte, ever.** A worker that sends one byte then fails (stream and non-stream) yields exactly one attempt, the existing error event, a breaker fault with no ticket, and an untouched budget.
7. **[C][D] Retry budget (D5).** Fake clock: allowed up to exactly the limit and the next denied; window rolls; minimum at low volume, ratio at high; models independent; overflow models share `other`; first attempts count only routed Number-1 attempts; the check precedes the retry's routing so **a denied retry fires no `AttemptStarted`/`AttemptEnded` and the attempts header stays 1**; a retry with no other worker refunds; a denial consumes nothing; concurrent requests cannot overshoot by more than zero (atomic reserve). Amplification against a 100%-failing worker never exceeds `1 + budget_ratio` plus the minimum allowance.
8. **[D] Deadline (D6).** Queue wait plus attempts never exceed the first-byte deadline plus a stated tolerance; no retry starts with less than `min_remaining`; expiry is 504 before any byte and ignored after the first; the derived default never shortens a single attempt; an explicit value below `upstream_header_timeout` is refused.
9. **[C][D] Breaker state machine (D7-D8),** deterministic with a fake clock and a randomized model check against a naive reference: both trip rules and their boundaries; a streak older than `window` does not count; open admits nothing until the jittered cool-down; half-open admits exactly `probe_concurrency`; `probe_successes` close and reset; a failed probe doubles up to the maximum; a **ticket is returned at the first byte** (a 60 s stream does not hold it) and on neutral, cancel and panic, exactly once; a later mid-stream abort records a fault without a ticket; the lost-ticket backstop releases; a new `RegisteredAt` resets; pruned workers vanish; the cool-down level persists across a pass-then-retrip and resets after `max_cool_down` closed; nothing depends on wall time.
10. **[C][D] Ejection cap (D9).** With fraction 0.5: 1 eligible → 0 open, 2 → 1, 3 → 1, 4 → 2, asserted as a table; workers UNHEALTHY/LOST/DRAINING/suspect are outside numerator and denominator (4 workers with 2 UNHEALTHY → at most 1 open); HALF_OPEN counts; a suppressed breaker keeps its window and opens on its next outcome once room exists; fraction 1 with all open gives fast `NO_CAPACITY` with `Retry-After` in 1-30.
11. **[D] Eligibility (D10).** An open breaker's worker is never selected (property test over random views **including breaker state**, `scheduler_ineligible_selections_total` 0); breakers never make a registry-ineligible worker eligible; `eligible_workers` excludes open workers; a lost ticket race re-selects inside `Route` before any observer fires and leaks no slot; `/readyz` ignores breakers.
12. **[C][E] Queue (D11-D12).** Depth never exceeds the maximum under 10x arrivals; **strict FIFO including arrivals** (an arrival with a non-empty queue enqueues); the freed slot is handed to the head waiter under `router.mu` with no re-route and no lost wake-up; a hand-off to a worker that became ineligible or open re-routes and keeps head position; a refresh wakes at most `min(waiters, free slots)`; a cancelled waiter leaves at once and goroutines return to baseline after 10,000 cancellations; `max_wait` honoured within tolerance; a retry never waits; no wait when no worker is eligible or the model has no queue (overflow models, client text); the Run A stale-count case is served by hand-off, not by waiting out the refresh; the tenant share caps one tenant's occupancy.
13. **[E] Shedding and Phase 8 interplay.** Each reason sheds as `503 NO_CAPACITY` with the right `Retry-After` (EWMA 1-10 for queue reasons, 1 for `global_limit` and `draining`), never a 429; the body shape is unchanged; pre-limiter sheds charge no quota; a queued request holds its lease and releases it on every exit; the global cap counts from after authentication and is documented against `inference_requests_active`; a shed feeds `admission_rejections_total` and **not** `scheduler_decisions_total`.
14. **[A][D][E] Seam (D13).** Fields and methods exactly as stated; sequences pinned in `observer_test.go` for queue-served (`QueueWaited(served)`, `AttemptStarted`), queue-timeout (`QueueWaited(timeout)`, `RequestRejected(overload, queue_timeout)`), shed without waiting (no `QueueWaited`), budget-denied retry (no second `AttemptStarted`), probe attempts (`Probe` true) and breaker transitions; tracing and events embedders compile and behave unchanged; the observer benchmark reports 0 allocs/op for the request-path metrics methods.
15. **[D][E] Cardinality and content (D14).** The all-registries label test passes with no new label names; `circuit_breaker_state` exports non-closed breakers only; with 1,000 workers and 1,000 models the new series stay within a bound added to the ADR-017 ceilings; the span allow-list test passes with the new keys; log, event and metric output contains no body, prompt, key or worker error text (hostile-input test); the overhead histogram excludes queue wait (a test with a queued request) and `inference_queue_duration_seconds` records it; the registry-mode golden differs by additions only.
16. **[C] Configuration (D1).** Defaults, YAML, env overlay, every bound and cross-check (`on` with static mode accepted; `queue.max_wait` ≤ deadline; explicit `first_byte_deadline` ≥ header timeout; `drain.readiness_grace` < `shutdown_timeout`; `probe_header_timeout` ≤ header timeout); malformed settings ignored while `off` or static; the env overlay follows the ignore-invalid convention and the docs say so.
17. **[F] Gateway drain (D16).** Process test: SIGTERM with a stream in flight → `/readyz` 503 within 200 ms (the 2 s cache bypassed), requests during the grace succeed with `Connection: close`, the stream completes, queued waiters finish or time out (no flush), the process exits after grace and drain, a second signal exits at once; the existing signal tests pass with grace 0.
18. **[F] Worker drain (D15).** Rolling replacement under load using `embedded.DrainWorker` with an announce above heartbeat plus refresh: zero client failures and zero `draining` retries; with announce 0 the same run shows the retries (reported, not failed).
19. **[B][D] Chaos tests (tests/chaos).** For freeze (lowered header timeout), error burst (`unavailable`, partial and 100%), connection reset and midstream: the breaker opens within the configured number of faults, client failures stop **except one per probe** (and the unavoidable midstream ones), probes never exceed `probe_concurrency`, the breaker closes after the fault ends and traffic returns; a slow-but-successful worker (delay below the header timeout) never opens a breaker; an always-500 worker is ejected through the ratio rule while its requests are never retried.
20. **[D] Rate-limit unavailability.** `RATE_LIMIT_UNAVAILABLE` never records a breaker verdict or consumes retry budget.
21. **[G] Silent agent and alerts (D23).** Re-measured numbers are in the benchmark note; the 5 s `warning` and 10 s `critical` alerts and the new alerts pass promtool; `scripts/quality.sh observability` passes; a heartbeat late by one interval never fires the critical alert.
22. **[B][E][G] Benchmark deliverable (D18-D21).** `docs/benchmarks/phase-15-chaos.md` has per scenario before/after tables of the two pre-registered measures plus descriptive ones with 3-repeat ranges and `SPREAD` verdicts, the invalid runs and their reasons, the Run A group, the `resilience: absent` baselines, what the embedded cluster cannot show (crash), and no claim from overlapping ranges; a scenario where the feature makes things worse is reported as such.
23. **[all] Quality gate.** `gofmt`, `go vet`, `go build`, `go test -race ./...`, `golangci-lint`, `scripts/quality.sh full`, CI steps run locally per PR; the chaos tests pass with `-race -count=10` and under CPU load (cool-down scaled by config, so a scenario is seconds, not tens of seconds).

## Risks

- **Retry amplification** is the failure this phase exists to prevent and the easiest to reintroduce (a high budget, `max_attempts` 5, retry-on-timeout later). Amplification is a reported measure and a bounded test (7). N gateways allow N times the budget.
- **Default-on surprises existing users.** An upgraded gateway changes behaviour with no configuration change (D25). Mitigations: the list in README, ADR-020, operations guide and PR text; the `off` kill switch; conservative defaults (budget 20%, cap 50%, queue 3 s, probe-only recovery); static deployments untouched; Run A and Phase 7 baselines reproducible with `off`; the flip is its own last PR and its own revert. Residual: an operator who reads nothing sees a 3 s delay before a 503, a live global cap and a worker missing from routing.
- **Breaker flapping and half-open herds.** Doubling cool-downs, one probe at a time, jitter and the cap limit it; N gateways each probe once per cool-down; one lucky probe can close a breaker (spec's example, `probe_successes` configurable); a worker at ~60% failure cycles through open/probe/close at the grown cool-down.
- **Opening on busy workers.** Misclassifying overload as fault would remove capacity when it is scarce: the neutral rows, the peek and the cap limit the damage; a real vLLM sidecar's 503 vocabulary is unknown and must be checked in Phase 13 (the code list is a constant to extend). Unlisted 5xx count only in the ratio rule.
- **A lying worker** can evade the breaker with `queue_full`; retries, the budget and heartbeat health still apply (trust boundary: registration).
- **Shedding the wrong traffic.** Tail drop is blind to value and size; tenant-blind apart from the 0.5 queue share; a shed after the quota charge is a double penalty; each gateway decides alone. Tenant-aware shedding is Phase 22.
- **Queue hides overload.** Under sustained overload every queued request waits `max_wait` then fails (worse latency for failures); the depth bound limits how many; the default `max_wait` is derived from the staleness window (heartbeat 2 s + refresh 1 s). Hand-off bypasses the scheduler strategy for the queued request (it inherits the freeing worker), a small, stated distortion of the strategy's distribution under queueing.
- **Interaction with drain.** A draining worker is neutral but retried, so a short announce is paid in retries; waiters at gateway drain finish within `max_wait`; requests arriving in the last milliseconds of the grace may still be cut by `Shutdown`, as today.
- **Snapshot staleness.** Breakers are local and faster than the registry; the only reset is a new `RegisteredAt`; a restart that keeps its registration is invisible.
- **Test flakiness under sleep and load.** Real-time pieces (listeners, TCP resets, cool-downs) need generous bounds; clocks are injected wherever logic allows; benchmark runs use `caffeinate` and the sleep/clock-step validity reason; `-count=10` under load before done. `TestAClientWhoLeavesStopsTheRetries` is known flaky under heavy CPU load (Phase 8 notes) and is not made worse.
- **Simulator limits.** One machine, loopback, mock workers with no batching or GPU contention: shapes, not capacity. macOS and Linux differ on TCP resets and closed listeners. The embedded cluster cannot show the breaker on a crash (the registry is faster); freeze and error bursts can.
- **Scope creep** toward the scheduler (Phase 14) or tenant fairness (Phase 22); each PR says what was left and why (D22).

### What cannot be verified on this machine

Real packet loss and partitions (`tc`/netem need Linux privileges); load-balancer deregistration, Kubernetes rolling updates and preStop (Phase 17-18); real vLLM error vocabulary and overload behaviour; multi-host clock skew; Linux TCP-reset behaviour except through CI. Anything not run is stated as such in the benchmark note and the PR.

#### PR D, second fix round (after the second verification, against c8f9893)

- **F1 (chaos `TestMidstreamFailures` flaky).** Reproduced by instrumenting a scratch copy (1 failure in 40 runs of the unchanged test): the failing run had `closes=4 opens=4 openNow=0` at the moment the fault was cleared (the breaker sat re-closed between two leaky cycles), so the wait `closes()>=1 && openNow()==0` passed at once; a stream already in flight then aborted, the breaker reopened (`opens=5 openNow=1`) and only 1 attempt reached the worker in the 800 ms window. Fix: the wait is now `closedAndSettled`, built right after the clear: a close counted after the clear (or a breaker already closed at that moment), nothing open or half-open, and no new open for 150 ms. Nothing asserted was loosened. A first version with a 500 ms quiet period failed the gate in 3-7 of 12 runs of the partial and all-requests scenarios: in this rig the recovered worker often stops being selected about 400-600 ms after its breaker closed (breaker closed, registry says READY, healthy and eligible, other workers serving). Probable cause, not proven: the least-active scheduler picks by the worker-reported `ActiveRequests`, which is a heartbeat (1 s) old, so a load figure taken during the recovery burst keeps the worker last for up to a second. It predates this round (the old wait hid it because its window started at the close). The quiet period is therefore 150 ms and only for leaky scenarios; the others wait for the close alone, as before. Evidence: `-race -count=30` clean (see the report of this round).
- **F2 (docs).** The "up to `min_volume` failed streams per cool-down cycle" figure was understated. The cost scales with the streams in flight on the worker (the ratio rule needs faults at half the window, and the window holds the in-flight oks). Simulation figures (not production data) are in ADR-020 and the operations guide: about 38 / 186 / 690 aborted streams per cycle for 2 s / 10 s / 60 s streams, median time to first ejection 3.8 s / 19 s / 69 s, workers aborting 20-30% or alternating ok and abort never ejected. Chaos comments say min_volume + 1 is this rig's short-stream bound only.
- **F4/F6.** `AttemptEnd.Verdict` after a stream abort is `fault` with outcome `failed` (asserted). `recordAfterRelay` already flushes; a test shows the breaker transition caused by the abort itself reaches the observers before any later request or refresh (fails if the flush is removed). The dropped count is reset after it is logged and not repeated (test; fails with `Load` instead of `Swap`). `Serve` now flushes on every return path, including a listener error (test failed before the change).
- **F5 seam.** `beforeEndPhaseHook` sits between `sendOnce` and the decision point, outside `arrived()`; the new test holds the caller there for three deadlines on four response paths. Removing `arrived()` on the retryable-status, non-retryable-status or 200 path now fails it (shown on hand mutants). `afterArrivalHook` is kept.
