# Phase 15 — Fault Tolerance: Circuit Breakers, Retry Budgets, Bounded Admission, Drain, and a Chaos Benchmark

Status: Proposed (awaiting approval of decisions D1-D24)
Owner: coding agent
Depends on: Phases 4-12 merged (master 4b9fd32): the registry and agents (4), the scheduler (5), retries and attempts (6), the benchmark harness (7), rate limits (8), the observer seam (prep, ADR-016), metrics (10), tracing (11) and events (12). Uses Phase 7 (`cmd/benchmark`) for the acceptance runs.
Spec: `docs/architecture/serverflow-spec.md` §6, §7, §11-12, §15-16, §24-27, §31, §36, §40, §58 Phase 15, §63
Hand-offs: ADR-012 ("circuit breakers (Phase 15) are the better answer" to timeouts, fast-failing workers, poison requests and retry multiplication; "a retry budget belongs with backpressure in Phase 15"); ADR-016 (the panic gap "planned for Phase 15"); ADR-015 / Phase 8 (the unknown-model quota charge; "global backpressure and queues stay in Phase 15"); ADR-017 (`inference_queue_duration_seconds` and `admission_rejections_total` deferred to this phase; a retry whose second routing fails is not counted); Phase 6 and 10 benchmark findings (below). Phase 14 (latency-aware scheduling) and Phase 22 (tenant fairness, priority) are explicitly not started here.

## Outcome

A failing worker costs clients almost nothing and the cluster says so. A worker that crashes, hangs, resets connections or fails every request is taken out of the gateway's routing within seconds, probed carefully, and brought back; retries cannot multiply an outage because they draw on a budget; a burst the workers cannot take waits a bounded time in a bounded queue or is refused fast with an honest `Retry-After`; a worker or a gateway can be drained under load without failed requests. The claim is measured with a chaos benchmark on the Phase 7 harness, before and after, and the plan states in advance what would count as working and what the simulator cannot show.

```text
client ─► gateway ── admission (global cap, per-model FIFO queue, max wait) ── shed: 503 + Retry-After
              │            │
              │            └─ router: registry view ∩ breaker.Admissible ─► scheduler ─► worker slot
              │                         ▲ outcome of every attempt (fault / ok / neutral)
              └─ retry only if: nothing sent to client ∧ attempts left ∧ budget ∧ deadline ∧ another worker
                 breaker per worker (closed ⇄ open ⇄ half-open), local to this gateway, lazy, no timers
```

Acceptance headline (spec §58): *chaos benchmark: kill, delay and break workers under load; documented recovery.* Everything new is behind `resilience.mode` (default `off`), so Phases 2-12 behave as before except for three listed bug fixes.

## Non-Goals

- No latency-aware, weighted or load-estimating scheduling, and no change to scheduler strategies or the rotor (Phase 14). No tenant fairness, priority queues or per-tenant shedding (Phase 22). No autoscaling (19).
- No hedged (parallel) requests, no retry after the first byte, no transparent stream restart (spec §25), no retry of header or idle timeouts (ADR-012 stays).
- No cluster-wide breaker or queue state: each gateway decides alone; nothing new in Redis, and the control plane is not told about breakers.
- No Kubernetes, load balancer or preStop behaviour (Phase 17-18); only the process-level contract they will rely on (D15).
- No real network faults (`tc netem`, packet loss, partitions) and no GPU/vLLM: the chaos runs are loopback and mock workers (Risks).
- No change to the Kafka event schema (v1 stays), the Postgres schema, or `pkg/protocol` wire types.

## Current Architecture (verified in code at 4b9fd32)

- **Attempts.** `forwardRegistry` (`internal/gateway/attempt.go`) routes, sends, and while nothing was written to the client retries on a different worker up to `gateway.max_attempts` (2). The next worker is found before the failed response is dropped. Retryable: connect, reset/EOF before headers, configured statuses (502, 503), an empty first chunk. Not retried: header timeout, stalled first byte, 500, 504, 4xx, anything after the first byte (ADR-012). The attempt's cleanup (`defer s.finishAttempt/idle.Stop/cancel`) is registered **after** the send loop.
- **Router** (`router.go`): cached registry view, `exclude` list, in-flight overlay `max(worker-reported, local)`, scheduler, slot reservation under one lock. It has no memory of past failures: a failure is remembered for that request only.
- **Scheduler eligibility** (`scheduler.Candidates`): READY, `Eligible` from the registry, healthy/suspect, `active < max_concurrency`. `NoWorkerError{Serving, Eligible, AtCapacity}` already separates "all dead" from "all full".
- **Registry** (`internal/registry`): states and heartbeat-age health; suspect 5 s, unhealthy 10 s, lost 30 s by default; a drain is one-way. The gateway ages heartbeats between refreshes (`snapshotCache.age`) so it stops routing to a silent worker once its age passes `suspectAfter`.
- **Admission today**: only Phase 8's per-tenant limiter. `admission.max_global_requests` (default 1000) exists in config, is validated, and is used by nothing. There is no gateway queue; "all workers full" is an immediate `503 NO_CAPACITY` with `Retry-After: 1`. Workers have their own bounded queue (`queue_size`, 503 `queue_full`), which the scheduler never fills because it excludes a worker at `max_concurrency`.
- **Drain.** Mock worker on SIGTERM: state `draining` (readiness 503, new requests 503 `draining`) immediately, waits for in-flight up to `--drain-timeout`. Agent on SIGTERM: reports DRAINING then deregisters at once. The gateway learns of either only at its next refresh (1 s default), so requests in that window hit a 503 and are retried. Gateway on SIGTERM: `http.Server.Shutdown` straight away (listener closes, in-flight finish up to `shutdown_timeout`, second signal exits). `/readyz` keeps answering 200 until the listener closes, so a load balancer gets no warning.
- **Mock worker failure injection** (`internal/mockworker/failure.go`): a seeded rate and one mode (`error` 500, `unavailable` 503, `drop`, `midstream`), fixed at start-up. No runtime control, no added delay (only static TTFT/tokens-per-second), no black hole, no crash/restart, no flapping. The embedded harness cluster (`internal/bench/embedded`) builds in-process mocks with 10 s registry thresholds and no fault hooks.
- **Observer seam** (ADR-016): seven request moments; metrics, tracing, events embed `NopObserver`. Series labels are an allow-list (ADR-017); span attributes an allow-list (`internal/tracing/attrs.go`); events carry no free text and have a closed `failure_class` set.
- **Config**: one file per feature under `internal/config`, a validator called from `Config.Validate()` (settings validated only when the feature is on), env overlay in `load.go` (invalid values ignored, a known quirk), defaults in `Default()`.

## Decisions (confirm before implementation)

- **D1 Switch, scope and configuration.** `resilience.mode: off | on`, default **off** (every earlier feature shipped off). Applies to registry mode only; `on` with `gateway.worker_source: static` is a validation error. New file `internal/config/resilience.go` (`ResilienceConfig` with `Breaker`, `Retry`, `Queue`, `Drain` sub-structs, `defaultResilience()`, `validate()`), validated only when `mode` is `on` (the Redis/events rule; the mode value itself is always checked), env overlay `SERVERFLOW_RESILIENCE_*` in `load.go`. No secrets, so no redaction. Keys and defaults:

  | Key | Default | Bounds |
  | --- | --- | --- |
  | `breaker.consecutive_failures` | 5 | 1-1000 |
  | `breaker.failure_ratio` / `breaker.min_volume` | 0.5 / 10 | 0-1 / 1-100000 |
  | `breaker.window` | 10s | 1s-10m |
  | `breaker.cool_down` / `breaker.max_cool_down` | 20s / 2m | 1s-1h, ≥ cool_down |
  | `breaker.probe_concurrency` / `breaker.probe_successes` | 1 / 1 | 1-16 / 1-16 |
  | `breaker.max_open_fraction` | 0.5 | 0-1 |
  | `retry.budget_ratio` / `retry.budget_min` / `retry.budget_window` | 0.2 / 10 / 10s | 0-1 / 0-1000 / 1s-10m |
  | `retry.first_byte_deadline` / `retry.min_remaining` | 60s / 1s | ≥ 1s (0 = none) / 0-1m |
  | `queue.max_model_depth` / `queue.max_wait` | 128 / 3s | 0-100000 (0 = no queue) / 100ms-60s |
  | `drain.readiness_grace` | 5s | 0-5m, < `gateway.shutdown_timeout` |

  The breaker defaults follow the spec's example ("5 failures within 10 s -> OPEN; wait 20 s -> HALF_OPEN; probe success -> CLOSED"). Cross-checks: `queue.max_wait` ≤ `retry.first_byte_deadline`; the global cap reuses the existing `admission.max_global_requests` (it was reserved for this, spec §16) rather than adding a second knob.
- **D2 Panic-safe attempts (debt 1), unconditional.** One deferred cleanup installed immediately after `routeAttempt` succeeds, acting on the *current* attempt through a variable the loop updates; it runs `release`, stops the idle timer, cancels, returns any breaker ticket (D8) and emits `AttemptEnded` with outcome `failed` and class `panic` exactly once (an `ended` flag prevents a double end). `routeAttempt` releases the slot itself if anything after `Route` panics. The panic still propagates to `withRequest` (500, `RequestCompleted`). The observer contract gains: *every `AttemptStarted` is followed by exactly one `AttemptEnded`, including on panic.*
- **D3 Model pre-check before the limiter (debt 2), unconditional.** In registry mode, before `admit`, ask the snapshot cache whether any worker serves the model (`snapshotCache.Serves(model)`, no copy). Unknown model: `RequestAdmitted` then `RequestRejected(model)` then 404 as today, but **no quota, token or concurrency lease is taken**. No usable snapshot: fall through to the limiter exactly as today (a missing view is not "unknown model"). A model that disappears between the check and routing still 404s after being charged (rare, documented).
- **D4 Failure taxonomy.** Each finished attempt yields one of: *ok*, *fault*, *neutral*. Fault means the worker is at fault and feeds the breaker; retry eligibility is unchanged from ADR-012 except where marked.

  | Event | Retried | Breaker | Note |
  | --- | --- | --- | --- |
  | connect error, dial refused/timeout | yes | fault | |
  | reset/EOF before headers; empty first chunk | yes | fault | |
  | 502 / configured retry status; 503 with an unknown or missing error code | yes | fault | |
  | 503 whose error code is `queue_full`, `draining` or `not_ready` | yes | **neutral** | load or lifecycle, not a fault; opening on a busy worker would shed capacity during overload |
  | header timeout; stall before the first byte; 504 | **no** (unchanged) | fault | duplicate GPU work stays refused; the breaker is the remedy |
  | stream aborted or errors after the first byte | no | fault | client already got bytes; nothing to retry |
  | 500, other 5xx not listed | no | **neutral** | may be deterministic; a poison request must not trip every breaker |
  | 2xx complete; 4xx relayed | no | ok / neutral | |
  | client disconnect; request deadline expiry | no | neutral | never a worker verdict |
  | `panic` (D2) | no | neutral | |

  To tell 503 causes apart the gateway reads at most 1 KiB of a *held retryable* 503 body, parses `error.code` and compares it with the three fixed strings; anything else (large, binary, malformed, absent) is a fault. The body is never logged, stored or used as a label. A registered worker can lie to dodge the breaker; workers are semi-trusted (registration is the trust boundary, Phase 4) and retries and the registry still apply (Risks).
- **D5 Retry policy upgrades.** `gateway.max_attempts` stays the per-request cap (default 2, unchanged). New per-model **retry budget**: a retry is allowed only if retries in the last `budget_window` < `max(budget_min, budget_ratio × first attempts in the window)`; windows are 1 s buckets. The budget is checked after the next worker is found and before it is used; a denied retry relays the failed attempt's response, like "no second worker" today (ADR-012). Per model, keyed by registry-confirmed model, capped like other model labels (`metrics.max_models`, overflow shares one `other` budget). **No backoff**: a retry goes to a different worker, so waiting buys nothing; backoff matters only for attempts ≥ 3, which the 2-attempt default does not use (revisit if `max_attempts` > 2 is run in anger). A retry is also not started when less than `retry.min_remaining` is left of the deadline (D6).
- **D6 Deadline.** `retry.first_byte_deadline` bounds the retryable phase only: queue wait plus all attempts until the first byte reaches the client; it is a context deadline on the request-scoped part of each attempt. Expiry before any byte: `504 UPSTREAM_TIMEOUT`. After the first byte it does not apply (idle timeout and client write timeout keep governing; spec §23: never buffer or cut a live stream). Client cancellation already propagates to the worker through the attempt context (spec §24, tested in Phase 6) and is unchanged. No deadline header is sent to workers (the mock would not read it; revisit with vLLM).
- **D7 Breaker model.** One breaker per worker, **local to each gateway**, keyed by worker ID and the snapshot's `RegisteredAt` (a re-registered worker is a new incarnation and starts closed). It counts only *fault* and *ok* (D4). It trips when either (a) `consecutive_failures` faults in a row, the first no older than `window`, or (b) at least `min_volume` outcomes in the sliding `window` (1 s buckets) with fault ratio ≥ `failure_ratio`. It never trips on latency alone: a merely slow worker is a scheduling problem (Phase 14). Breakers for workers missing from the snapshot are pruned on refresh (memory bounded by `control_plane.max_workers`).
- **D8 States, cool-down, probes.** CLOSED → OPEN on trip; OPEN → HALF_OPEN lazily when `cool_down` (±20% jitter from an injected source, so gateways do not probe in lockstep) has elapsed, evaluated on `Admissible`/`Acquire` with an injected clock, **no timers or goroutines**. HALF_OPEN admits at most `probe_concurrency` real requests (the probes); `probe_successes` consecutive ok outcomes close it and reset its counters; a fault reopens it with the cool-down doubled up to `max_cool_down`; a neutral outcome returns the ticket without a verdict. Probes are live requests, not synthetic GETs: a worker whose readiness answers but whose inference fails is exactly the case to catch, and a failed probe is retried on another worker like any first attempt. A probe ticket is held by the attempt and returned in the D2 cleanup; a ticket outstanding for more than twice the cool-down is treated as lost.
- **D9 Ejection cap.** At most `max_open_fraction` (0.5) of a model's workers, rounded down, may be OPEN at once; a breaker that wants to trip while the cap is reached stays closed and counts `breaker_trip_suppressed`. A model with one worker therefore never opens (there is nowhere else to send traffic, and a correlated false positive must not empty a model). With `max_open_fraction: 1` and all workers open, routing returns `NO_CAPACITY` fast with `Retry-After` = time to the earliest half-open, clamped to 1-30 s.
- **D10 Eligibility integration.** The router filters the registry view with the breaker **after** `View()` and the exclusion list and **before** the scheduler: workers that are not `Admissible` are marked ineligible in the copy (`Eligible=false`), which reuses the scheduler's filter and keeps `eligible_workers` in `NO_CAPACITY` bodies truthful. The chosen worker then calls `Acquire` (takes a probe ticket if half-open); if a race lost the ticket the router drops that worker and re-selects, at most once per candidate. The registry stays authoritative: breakers only remove workers, never add; UNHEALTHY/LOST/DRAINING/suspect still exclude as before. The control plane and `/v1/workers` are unchanged; breaker state is exported by the gateway only.
- **D11 Admission queue and shedding.**
  - *Where.* A request waits only when its **first** routing finds the model served and eligible workers all full (`NoWorkerError.AtCapacity > 0 && Eligible == AtCapacity`). No eligible worker at all, an unknown model, or a stale registry view is an immediate 503/404 as now; a retry's second routing never waits.
  - *Shape.* Per model, FIFO, depth ≤ `queue.max_model_depth`, each waiter ≤ `queue.max_wait` and ≤ the remaining first-byte deadline. Waiters wake in FIFO order: one on every slot release for the model, up to `min(waiters, free slots)` on every registry refresh (a refresh is when stale counts correct themselves); a woken waiter that still finds no slot returns to the **head**. A cancelled waiter is removed at once. No goroutines per waiter beyond the request's own.
  - *Global cap.* `admission.max_global_requests` bounds requests admitted and not yet completed (queued plus running) on this gateway; over it, new arrivals are refused immediately.
  - *Shedding order*, all `503 NO_CAPACITY` with `Retry-After` (the spec allows 429 or 503; **429 stays reserved for the tenant's own quota**, `RATE_LIMITED`, because overload is not the caller's fault): (1) a client that left is dropped silently (499, not shed); (2) global cap reached → refuse the arrival, `global_limit`; (3) model queue full → refuse the arrival (tail drop), `queue_full`; (4) a waiter past `max_wait` → `queue_timeout`, oldest first; (5) gateway draining → flush the queue, `draining`. Running requests and retries are never shed. `Retry-After` = EWMA of recent queue waits, rounded up, clamped 1-10 s (1 with no data).
  - *Order with Phase 8.* Pre-limiter cheap checks (global cap, model queue already full) run before `admit` so a refusal there spends no quota; `queue_timeout` happens after the charge and is **not refunded** (Phase 8 has no refunds; documented). A queued request holds its concurrency lease. Tenant fairness is Phase 22.
- **D12 Admission and the other queues.** Spec §27's `max_worker_queue` stays the worker's own bounded queue (503 `queue_full`, neutral under D4); `max_tenant_concurrency` is Phase 8. Nothing else in the gateway queues; all new queues are bounded by construction (acceptance 12).
- **D13 Observer seam additions (explicit; documented in `docs/development/observers.md`, ADR-020 amends ADR-016).**
  - `AttemptEnd` gains `NextRouteResult` (`""`, `no_capacity`, `worker_unavailable`, `error`) so metrics counts the failed second routing (debt 3, unconditional), and `RetryDenied` (`""`, `budget`, `deadline`).
  - `Rejection` gains kind `overload` with reasons `global_limit`, `queue_full`, `queue_timeout`, `draining`; its `Model` rule is unchanged.
  - New method `QueueWaited(ctx, QueueWait{RequestID, Model, Waited, Result})` (`served`, `timeout`, `client_gone`, `drained`), fired once for a request that actually waited, between `RequestAdmitted` and `AttemptStarted`/`RequestRejected`.
  - New method `BreakerTransition(ctx, BreakerChange{WorkerID, Model, To, Reason, Failures, CoolDown})` for CLOSED/OPEN/HALF_OPEN changes. It is not tied to a request, so `ctx` is background. `NopObserver` supplies defaults; tracing and events embed it and compile unchanged. The new methods are never called with `resilience.mode: off`.
  - A one-line contract: `AttemptEnded` always follows `AttemptStarted` (D2).
- **D14 Metrics, spans, events, logs.** Everything below registers **only when `mode: on`**, so with it off `/metrics` is byte-identical and the golden series files do not change except for debt 3's counter values. Labels come from the existing allow-list (`model, reason, state, worker_id`); no new label names.
  - Event instruments: `circuit_breaker_transitions_total{model,state}` (`state` = the state entered), `retries_denied_total{model,reason}` (`budget|deadline`), `admission_rejections_total{model,reason}` (`global_limit|queue_full|queue_timeout|draining`), `inference_queue_duration_seconds{model}` (histogram, requests that waited), `breaker_trips_suppressed_total{model}`. These are the two series ADR-017 deferred to this phase.
  - Collectors (read at scrape, ADR-017): `circuit_breaker_state{worker_id,model}` (0 closed, 1 half-open, 2 open; live workers only), `circuit_breakers_open{model}`, `admission_queue_depth{model}`, `gateway_draining`.
  - Logs: one line per breaker transition (WARN on open, INFO otherwise: worker_id, model, from, to, reason, failures, cool_down_ms), one per shed (INFO, rate-limited to 1/s per reason with a suppressed count), retry denial at DEBUG; never a body, prompt, key or worker error text.
  - Spans: only the existing attempt/request spans gain span events `queue.wait` and `retry.denied` and the attributes `serverflow.queue.wait_ms`, `serverflow.queue.result`, `serverflow.breaker.state` added to `AllowedKeys` (the allow-list test must pass); no client text.
  - Events (Kafka): schema v1 unchanged. A shed request is already a `failed` event with `failure_class=no_capacity`; breaker transitions are worker events, not request lifecycle, and are not published.
  - Grafana/rules: one added dashboard "Resilience" (breaker state per worker, retries denied, queue depth/wait, sheds) and two alerts (`ServerFlowCircuitOpen` warning, `ServerFlowShedding` warning) with promtool tests; the existing "every dashboard metric is exported" test covers them.
- **D15 Worker drain.** The contract the platform relies on: *announce, then refuse, then finish.* The mock worker gains `--drain-announce` (default **0**, today's behaviour): on SIGTERM it reports `draining` (readiness 503, `/stats` status `draining`, so the agent heartbeats DRAINING) but keeps serving new requests for the announce period (set above heartbeat interval plus registry refresh in clusters and the chaos runs), then refuses new work, then finishes in-flight up to `--drain-timeout`. The agent already reports DRAINING then deregisters; it is unchanged. With the registry having removed the worker and the gateway refreshed, a rolling replacement under load shows no `draining` 503s. A drain that exceeds its timeout still cuts in-flight requests (documented, unchanged). Real preStop and readiness wiring is Phase 17.
- **D16 Gateway drain.** With `mode: on`, on the first SIGTERM/SIGINT: (1) `/readyz` returns 503 immediately and `gateway_draining` is 1; (2) for `drain.readiness_grace` (5 s) the listener stays open and requests are served normally, responses carry `Connection: close`; (3) the queue is flushed with `draining` sheds; (4) `Shutdown` runs with `shutdown_timeout` as today; a second signal still exits at once; the metrics listener still outlives the drain (Phase 10). With mode off nothing changes.
- **D17 Mock worker runtime faults.** New `mockworker.Faults`, an in-process handle with atomic settings read by `handleChat`/`handleReadyz`: `SetErrorRate(rate, mode)`, `SetExtraDelay(d)` (before response headers; the "slow worker, 5 s"), `SetBlackhole(bool)` (accept, read the request, never answer; "frozen worker"), `SetUnready(bool)` (flapping health), `Crash()` / `Restart()` (close listener and connections with a reset; listen again on the same port). Zero value = no fault, so existing tests and flags are untouched. No admin HTTP endpoint (no new attack surface); process-level chaos uses SIGKILL/SIGSTOP/SIGCONT in `make chaos-*`. The same handle exposes counters ("requests the fault touched") used as evidence that a fault was applied.
- **D18 Chaos harness.** `cmd/benchmark chaos --scenario <name>` on the Phase 7 packages (`internal/bench/chaos` for scenarios and phase accounting; `embedded.Cluster` exposes `Faults(workerID)`, the gateway metrics gatherer, and `Config.GatewayMutate` so the harness can set `resilience` without importing it). A run has three measured windows: *baseline* (no fault), *fault* (from the scenario's first action to its end or to `--fault-duration`), *recovery* (after). Scenarios: `worker-crash` (kill, optionally restart), `worker-freeze` (blackhole), `slow-worker` (5 s extra delay; run with header timeout above and below the delay, the first must **not** open a breaker), `error-burst` (rate and mode `unavailable`/`error`), `flapping` (unready on/off), `midstream` (mode `midstream`), `conn-reset` (mode `drop`), `drain-roll` (D15, one worker at a time), `overload` (clients above surviving slots, to exercise queue and shedding). Results are additive to `result.json` (`chaos`: per-window summaries, one-second success/latency series, fault-applied evidence). Redis failure and Kafka outage (spec §36) are **not** harness scenarios (the harness cannot authenticate) but `tests/chaos` integration tests over the existing proxy/broker fixtures (D19).
- **D19 What "works" means (no numbers invented).** All comparisons are relative to a measured baseline and use the Phase 7 3-repeat spread rule; absolute bounds come only from configuration or the spec.
  - *Success rate in the fault window*, split by client-visible error code.
  - *Time to isolate*: fault start to the first one-second bucket after which the faulty worker receives no first attempts except probes (from `scheduler_selections_total{worker_id}` deltas). Spec §31 bound: < 10 s for crash and freeze.
  - *Time to recover*: fault start (or fault end for transient faults) until 5 consecutive one-second buckets (with at least 5 requests) have a success ratio ≥ the baseline window's ratio.
  - *Retry amplification*: mean attempts per request in the window (`X-ServerFlow-Attempts`, 1 when absent) and retries denied.
  - *Tail latency*: p95/p99 of successful requests in the fault window against the baseline window; and the latency of failures (time to fail).
  - *Bounds that must hold absolutely*: queue depth ≤ `max_model_depth`, queue wait ≤ `max_wait` plus a stated test tolerance, goroutines and memory back to baseline after the run, no request routed to a non-READY worker (`scheduler_ineligible_selections_total` = 0).
  - *Validity gate (chaos).* A run is invalid when: the baseline window alone exceeds `--max-error-rate`; the fault is not evidenced (D17 counters, or the control plane not showing the worker unavailable); closed-loop clients exceed `SafeSlotFraction` of the **surviving** slots (except the `overload` scenario, which sets the opposite check); fewer than a minimum of requests land in a window; the cluster did not settle; the harness fell behind (open loop); the working tree is dirty or the commit is not recorded. Invalid runs are listed and never compared.
- **D20 Before/after.** Baseline = **master's gateway under the same harness**: the harness and mock-fault commits (D17, D18) are the first commits of the implementation, touch no gateway code, and are cherry-picked onto a scratch worktree of master to produce the "before" runs (the run records the commit). "After" = the branch with `resilience.mode: on`. A third group, branch with `mode: off`, must agree with the baseline within spread (a behavioural check, not a claim). Each group: 3 repeats, same seed, same flags, Mac awake (`caffeinate`, Phase 8's clock lesson), no other load. Reported: per scenario a table of the D19 numbers with min-median-max and the `SPREAD` verdict; an effect is claimed only when ranges do not overlap, otherwise "no distinguishable difference".
- **D21 Run A reproduction (debt 5).** One additional group on the Phase 10 "Run A" configuration (default worker concurrency 4, 12 clients, least-active) with the queue on, against master and mode off: reports the `NO_CAPACITY` share, queue wait, and validity. No target is asserted; if the queue does not bring the run under the 5% validity bound the benchmark note says so and the root cause is handed to Phase 14.
- **D22 Scheduler-owned items stay with Phase 14.** The rotor still advances on a retry, and the overlay still trusts a stale reported count; Phase 15 changes neither. The breaker removes the *sustained* herding case (a worker that always fails opens within `consecutive_failures` attempts); the benchmark reports what remains for a partially failing worker.
- **D23 Silent-agent detection (debt 6).** Defined as "the gateway stops routing to a worker whose agent went silent" (bounded by suspect_timeout 5 s + refresh + the request path, already in code), measured as *time to isolate* in the `worker-freeze` scenario with the agent also frozen. The alert `ServerFlowWorkerHeartbeatStale` threshold moves from 10 s to the suspect threshold (5 s), with its promtool test, and the Phase 10 kill experiment is repeated and the new number reported even if still above 10 s. If it is, the benchmark note says the scrape-plus-evaluation latency makes the alert chain longer than the routing path and leaves the number as is.
- **D24 Documentation and decision record.** ADR-020 (breaker, budget, queue, shedding semantics, drain contract, seam additions, defaults and why), `docs/operations/resilience.md` (configuration, metrics, runbook: "worker flapping", "everything is shedding", "breaker will not close"), `docs/benchmarks/phase-15-chaos.md`, updates to `docs/development/observers.md`, `ARCHITECTURE.md` ("There is no circuit breaker yet" is removed), README, and the Phase 6/10 notes' "left for Phase 15" lines.

## Proposed Design

**Package `internal/resilience`** (new; imports only `time`/stdlib and `internal/config` types; no gateway import, so it is testable with a fake clock and does not create cycles): `Breaker` and `Breakers` (map by worker, `Admissible(w, regAt)`, `Acquire`, `Record(ticket, outcome)`, `Prune(live)`), `Budget` (per-model sliding window), `Queue` (per-model FIFO waiters, `Wait(ctx, model, maxWait) Result`, `Wake(model, n)`, `Flush()`), `Admission` (global counter). Clock, jitter and time are injected. All state is behind small mutexes; nothing runs on a goroutine of its own.

**Gateway changes** (`internal/gateway`): `resilience.go` (option `WithResilience(cfg)`, wiring, drain state), `attempt.go` (single cleanup, budget and deadline checks, outcome classification into `Record`), `router.go` (breaker filter and `Acquire`, wake on release, `Serves`), `snapshot.go` (`Serves`, refresh notifies the queue and prunes breakers), `handlers.go` (pre-limiter checks, queue wait before first routing), `observer*.go` (D13), `metrics.go` (D14, registered only when on), `server.go` (drain sequence), `ratelimit.go` (order).

**Request flow with resilience on** (registry mode): parse → model allowed → *model served?* (D3) → *global/queue pre-check* (D11) → rate limit (unchanged) → route (registry view ∩ breakers) → if all eligible workers full, wait in the model queue → send → classify → on a retryable result: next worker (excluding tried), budget, deadline, attempts → relay. Every attempt end calls `breakers.Record(outcome)` and returns its ticket in the same cleanup that releases the slot.

**Chaos tests vs harness runs.** `tests/chaos` holds deterministic, assertion-based scenarios (fast: tens of seconds each) that run under `go test` and in CI, using the embedded cluster and `Faults`: they assert behaviours (opens, probes, closes, no retry after first byte, queue bounds, drain without failures). `benchmark chaos` produces the *numbers* and is run by hand (and in the nightly job, results not gated); `make chaos-worker-kill`, `chaos-worker-delay`, `chaos-network-loss` (spec §36 names) wrap the corresponding scenarios; network loss is `conn-reset` plus `worker-freeze` on loopback, not packet loss.

## Acceptance Criteria

1. **Panic safety (D2).** For a panic injected at each of: `RequestRecorder` before the first attempt, `sendAttempt`, the recorder after a retry's routing, and an observer — the worker's in-flight count returns to 0, `AttemptEnded(failed, class=panic)` fires exactly once per started attempt, a half-open ticket is returned, the client gets a 500 or an aborted connection, and `RequestCompleted` fires once. Fails on master (shown first).
2. **Model pre-check (D3).** With a limiter, an unknown model returns 404 and the tenant's request, token and concurrency counters are unchanged; a known model is charged as before; with no usable snapshot the limiter still runs; the observer sequence is `Started, Admitted, Rejected(model), Completed`.
3. **Second-routing metric (debt 3).** A retry whose second routing fails increments `scheduler_decisions_total{result}` and `scheduler_no_capacity_total` once, with the right result and reason, and nothing else changes.
4. **Off means off.** With `mode: off` (and in static mode) a differential run of the existing request matrix against master is byte-identical in status, body, headers (minus per-request IDs and dates), normalized log lines and `/metrics` series names, apart from the three listed fixes (D2 in the panic path only, D3, debt 3). No new series exist.
5. **Taxonomy (D4).** A table-driven test covers every row: retried or not, ok/fault/neutral, including 503 with each of `queue_full`, `draining`, `not_ready`, an unknown code, an oversized body, binary, malformed JSON and no body; the body read never exceeds 1 KiB.
6. **No retry after the first byte, ever.** A worker that sends one byte then fails (stream and non-stream) yields exactly one attempt, the stream ends with the existing error event, the breaker sees a fault, and the retry budget is untouched.
7. **Retry budget (D5).** With a fake clock: retries are allowed up to exactly the limit and the next is denied (`budget`), the window rolls and allows again, the minimum applies at low volume, the ratio at high volume, models are independent, an unknown-model flood cannot grow the map beyond its cap, and a denied retry relays the original worker response. Amplification in a 100%-failing-worker run never exceeds `1 + budget_ratio` plus the minimum allowance.
8. **Deadline (D6).** Queue wait plus attempts never exceed `first_byte_deadline` plus a stated tolerance; no retry starts with less than `min_remaining` left; expiry yields 504 `UPSTREAM_TIMEOUT` before any byte and is ignored after the first byte.
9. **Breaker state machine (D7-D8),** deterministic with a fake clock: closed to open on the consecutive rule and on the ratio rule (boundary values: threshold-1 does not trip, threshold does; below `min_volume` does not trip by ratio); a streak older than `window` does not count; open admits nothing until the jittered cool-down; half-open admits exactly `probe_concurrency` probes; `probe_successes` successes close and reset counters; a failed probe reopens with doubled cool-down up to the maximum; a neutral probe returns its ticket; a lost ticket expires; a new `RegisteredAt` resets the breaker; pruned workers disappear; the state is never a function of wall time without the injected clock.
10. **Ejection cap (D9).** In a 4-worker model with `max_open_fraction: 0.5` a third breaker never opens and `breaker_trips_suppressed_total` counts it; a single-worker model never opens; with fraction 1 and all open, requests get fast `NO_CAPACITY` with `Retry-After` in 1-30.
11. **Eligibility (D10).** An open breaker's worker is never selected (property test over random registry views, with `scheduler_ineligible_selections_total` staying 0); registry-ineligible workers are never made eligible by the breaker; `eligible_workers` in the 503 body excludes open workers; a lost probe-ticket race re-selects without leaking a slot.
12. **Queue (D11-D12).** Depth never exceeds `max_model_depth` (hammer test with 10x arrivals); FIFO order is preserved (including after a woken waiter returns to the head); no lost wakeup (a release between enqueue and park still wakes); a cancelled waiter leaves immediately and goroutines return to baseline after 10,000 cancelled waiters; `max_wait` is honoured within the test tolerance; global cap, queue-full, timeout and draining each shed with the right reason, `503 NO_CAPACITY`, `Retry-After` between 1 and 10, never a 429; a retry never waits; no wait when no worker is eligible.
13. **Phase 8 interplay.** Pre-limiter sheds charge no quota; a queued request holds its concurrency lease and releases it on every exit (served, timeout, cancel, panic, drain).
14. **Seam (D13).** `AttemptEnd`, `Rejection`, `QueueWaited` and `BreakerTransition` carry exactly the stated fields; sequences are pinned in `observer_test.go` for queue-served, queue-timeout, shed, budget-denied retry and breaker transitions; `NopObserver` embedders (tracing, events) compile and behave unchanged; the observer benchmark still reports 0 allocs/op for metrics in the steady state.
15. **Cardinality and content rules (D14).** The all-registries label test passes with no new label names; with 1,000 workers and 1,000 models the new series stay within a stated bound added to the ADR-017 ceilings; the span allow-list test passes with the three new keys; log and event output contains no body, prompt, key or worker error text (hostile-input test); with `mode: on` the golden series files differ by additions only, regenerated deliberately.
16. **Configuration (D1).** Defaults, YAML, env overlay, every bound and cross-check (including `on` with static mode, `queue.max_wait` > deadline, `drain.readiness_grace` ≥ `shutdown_timeout`); malformed settings are ignored while `mode: off`; the env overlay follows the repo's ignore-invalid convention and the doc says so.
17. **Gateway drain (D16).** A process test: SIGTERM with a stream in flight → `/readyz` 503 within 200 ms, new requests still succeed during the grace with `Connection: close`, the in-flight stream completes, the queue is flushed with `draining` sheds, the process exits after the grace and drain, and a second signal exits at once.
18. **Worker drain (D15).** Rolling replacement of each worker in turn under load with `--drain-announce` set above heartbeat plus refresh: zero client failures and zero `draining` retries; with announce 0 the same scenario shows the retries (reported, not failed).
19. **Chaos tests (tests/chaos).** For crash, freeze, error burst, connection reset, midstream failure and flapping: the faulty worker's breaker opens within the configured number of attempts, client failures stop (or are only the unavoidable midstream ones), probes occur at most `probe_concurrency` at a time, the breaker closes after the fault is removed and traffic returns, and a slow-but-successful worker (delay below the header timeout) never opens a breaker.
20. **Redis and Kafka (spec §36).** With the existing fixtures: Redis cut with `on_failure: closed` gives `503 RATE_LIMIT_UNAVAILABLE` within the Redis timeout, never trips a breaker or consumes retry budget, and recovers; Kafka down keeps inference succeeding, events drop with their metric, shutdown stays bounded (the Phase 12 bound). These run where the servers exist and are must-run in CI, skip locally with a notice.
21. **Silent-agent and alert (D23).** The re-measured numbers are in the benchmark note; the promtool test for the changed alert passes; `scripts/quality.sh observability` passes.
22. **Benchmark deliverable (D18-D21).** `docs/benchmarks/phase-15-chaos.md` has, for each scenario, before/after tables for the D19 measures with the 3-repeat ranges and `SPREAD` verdicts, the invalid runs listed, the Run A group, what could not be shown, and no claim from overlapping ranges. A scenario where the feature makes things worse is reported as such.
23. **Quality gate.** `gofmt`, `go vet`, `go build`, `go test -race ./...`, `golangci-lint`, `scripts/quality.sh full`, and the CI steps run locally; the chaos tests pass with `-race -count=10` and under CPU load.

## Risks

- **Retry amplification** is the failure this phase exists to prevent and the easiest to reintroduce: a budget set too high, a per-request cap raised to 5, or retry-on-timeout later enabled. The amplification factor is a reported measure and a bounded test (acceptance 7).
- **Breaker flapping and a thundering half-open.** A worker that fails intermittently can reopen repeatedly; mitigations are doubling cool-downs, one probe at a time, jitter, and the ejection cap. Several gateways each probe once per cool-down, so a recovering worker may see one probe per gateway at once; accepted, documented. A single lucky probe can close a breaker (spec's example); `probe_successes` is configurable.
- **Opening on busy workers.** Misclassifying overload as fault would remove capacity exactly when it is scarce. The D4 neutral rows, the body peek and the cap limit the damage; a real vLLM sidecar's 503 vocabulary is unknown and must be checked in Phase 13 (the peek's code list is a constant to extend).
- **A lying worker** can evade the breaker by sending `queue_full`; retries, the budget and the registry's heartbeat health still apply. Documented as the trust boundary.
- **Shedding the wrong traffic.** Tail drop and FIFO are blind to tenant, model value and request size; a large prompt and a trivial one are equal. Tenant-aware shedding is Phase 22. A shed after the quota charge is a double penalty for the tenant (no refund until a later phase).
- **Queue hides overload.** Waiting turns an instant 503 into a delay; under sustained overload every request waits `max_wait` then fails, which is worse latency for failures. The depth bound limits how many; the benchmark's `overload` scenario reports it and the default `max_wait` is derived from the staleness window (heartbeat 2 s + refresh 1 s), not tuned.
- **Interaction with drain.** A draining worker is neutral to the breaker (not a fault) but retried, so a long announce gap is paid in retries; a gateway draining flushes the queue and stops accepting at the end of the grace — requests arriving in the last milliseconds of the grace may still be cut by `Shutdown`, as today.
- **Snapshot staleness.** Breakers are local and faster than the registry, but a worker re-registering under the same ID with a different `RegisteredAt` is the only reset; a restart that keeps its registration after the registry lost it is invisible.
- **Test flakiness under sleep and load.** The chaos tests have real time in them (listeners, TCP resets, cool-downs). Phase 8 showed laptop sleep and VM clock steps invalidating timing; the plan uses injected clocks wherever the logic allows, polling with generous bounds elsewhere, `caffeinate` for benchmark runs, and `-count=10` under load before declaring done. One existing flaky test (`TestAClientWhoLeavesStopsTheRetries` under heavy CPU load, documented in Phase 8) is known and is not made worse.
- **Simulator limits.** The cluster, the load generator and the gateway share one machine over loopback; the mock worker has no batching, memory or GPU contention, so overload and slow-worker behaviour are shapes, not capacity. macOS and Linux differ in how a closed listener and TCP resets behave, so CI (Linux) results can differ from this Mac's. Numbers compare configurations with each other, not against hardware.
- **Scope creep** toward the scheduler (Phase 14) or tenant fairness (Phase 22); the PR says what was left and why (D22).

### What cannot be verified on this machine

Real packet loss, partitions and latency (`tc`/netem need Linux privileges); load-balancer deregistration, Kubernetes rolling updates and preStop (Phase 17-18); real vLLM error vocabulary and overload behaviour; multi-host clock skew; Linux-specific TCP reset behaviour except through CI; the Redis and Kafka scenarios here only if Colima's Docker is running (not exercised while planning). Anything not run is stated as such in the benchmark note and the PR.
