# Phase 11 — OpenTelemetry: Distributed Tracing

Status: Proposed (awaiting approval of the decisions below)
Owner: coding agent
Depends on: the prep PR (`docs/plans/active/prep-lifecycle-observer-and-config-split.md`: the `gateway.Observer` seam and the per-feature config split) merged first. Phases 6 (attempts), 8 (rate limit) and 9 (auth) are merged.
Spec: `docs/architecture/serverflow-spec.md` §6 (lifecycle, step 23), §7 (IDs, `trace_id`, attempt history), §8, §10, §12, §23, §25, §28, §58 Phase 11, §63
Hand-offs: Phase 10 (Prometheus) is built in parallel and edits `metrics.go`; this phase adds no metric code there. Phase 12 (Kafka) can read the trace ID from the context helper added here. Phase 16 owns the full compose; this phase ships one standalone Jaeger file and says how it is replaced. Phase 13 (real vLLM workers) must propagate `traceparent` if the worker agent ever becomes a request proxy.

## Outcome

Pick any request and see its whole life in one trace, across two processes: the gateway's work (receive, rate limit, scheduler, each attempt on each worker, first token, completion) and the worker's work (queue wait, inference), joined by W3C `traceparent`, with request ID, attempt ID and worker ID on the spans. A retried request shows two worker attempts under one request. Tracing is **off by default** and costs nothing when off; when on, a dead collector can never slow or fail a request.

```text
client ─► gateway ───────────────────────────────────► mock worker
          gateway.receive (SERVER)                      inference (SERVER)  ◄─ traceparent
           ├ rate_limit                                  └ queue_wait
           ├ scheduler.select  #1
           ├ worker.forward    #1 (CLIENT) ──────────────► ...  [event: retry]
           ├ scheduler.select  #2
           └ worker.forward    #2 (CLIENT, link → #1) ───► inference ...
               ├ first_token                (attempt start → first chunk)
               └ completion                 (first chunk → end of relay)
        both processes ─ OTLP/HTTP ─► collector / Jaeger
```

Acceptance headline (spec §58): *traces end to end; break spans; pick a request and inspect its full distributed trace.* "Break spans" is read as: the span structure survives (and shows) retries, rejections, client disconnects, worker failures and a dead collector.

## Non-Goals

- No metrics via OpenTelemetry (Phase 10 uses the Prometheus client) and no OTel logs. The OTel SDK's metric and log modules are not added.
- No spans for the worker agent or control plane: neither is on any request path (verified: the agent only calls its backend's `GET /stats` and the control plane's register/heartbeat; the gateway's registry polling is background work). No spans for Postgres, Redis or auth lookups, and no auto-instrumentation libraries (`otelhttp`, `otelpgx`, `redisotel`). Hand-written spans only, so every attribute is chosen (D9).
- No tail sampling, no baggage, no trace-based alerting, no exemplars, no span metrics. No auth headers for the collector (put a collector in front; see D13).
- No tracing of `/healthz`, `/readyz`, `/metrics`, `/v1/models` (probe traffic would flood the backend).
- No change to scheduling, retry policy, rate-limit or auth behaviour, to response bodies, or to any existing log or metric.
- No change to the benchmark harness; it may later read `trace_id` from logs.

## Current Architecture

- `X-Request-ID` (`req_<16 hex>`) is created in `withRequest` and returned to the client; `X-Attempt-ID` (`att_…`) is created per attempt in `routeAttempt` and sent upstream with `X-Request-ID`. The mock worker logs both. There is no `trace_id` anywhere yet, though spec §28 says logs "always" include it.
- `httpUpstream.Do` builds the worker request from an **allow-list** of headers (`Content-Type`, `Accept`, `User-Agent`, `X-Request-ID`, `X-Attempt-ID`); client headers (including `Authorization`) never cross. The per-attempt context `run.ctx` is `context.WithCancel(withAttemptID(r.Context(), id))` and is what `Do` receives. The attempt ID already travels as a **context value turned into a header** in `Do`; the same pattern fits trace headers.
- Retry (ADR-012): `forwardRegistry` loops `routeAttempt` → `sendAttempt` → (if retryable and `len(attempts) < max`) route to another worker, `abandonAttempt`; attempt history is only appended to. Static mode (no registry) calls `upstream.Do` directly and records a synthetic worker `"static"`, attempt 1.
- `relayStream` measures TTFT in `onData` from the handler's `start`; `info.ttft` is request-level, not attempt-level. A failure after output starts ends the stream with an SSE error and no retry (§25); a body failure after headers panics with `http.ErrAbortHandler`, which `withRequest` recovers.
- The mock worker (`internal/mockworker/server.go`): `handleChat` reads the body, rolls an injected failure, `engine.Acquire` (queue wait), then `generate`/`streamResponse`. It logs `queue_ms`, `ttft_ms`, outcome. It has flags, not a config file, and no `/metrics`.
- The collector skeleton in `docker-compose.yml` and `observability/otel/otel-collector.yml` (contrib 0.105.0, OTLP receivers on 4317/4318, `debug` exporter) is untouched by any phase. Docker (Colima) is installed on the user's Mac; it is not exercised by CI.
- Module facts measured in a scratch module (not in the repo): `go.opentelemetry.io/otel*` **v1.47.0 requires Go 1.26.0**; v1.46.0 requires Go 1.25.0 (the repo floor). Dependabot is active, so a v1.47 bump PR will arrive and must be refused or accompanied by a deliberate floor change.

## Decisions (confirm before implementation)

Say "approve all defaults" to accept every **default**.

- **D1 Gateway tracing is a second `gateway.Observer`.** It lives in `internal/tracing/gwtrace` and is registered with `gateway.WithObserver` after metrics, by `cmd/gateway`, only when `tracing.enabled`. OpenTelemetry is imported **only under `internal/tracing/...`** (the same confinement as go-redis in `internal/redis`); `internal/gateway` gains no OTel import. `internal/tracing` (core: setup, sampler, propagator, allow-list, stats) imports nothing internal; `gwtrace` imports `internal/gateway` (types only); `internal/mockworker` imports the core. No cycle.
- **D2 Seam extension (the Observer alone cannot do this): `RequestStarted` and `AttemptStarted` return a `context.Context`.** Reason: W3C propagation needs the worker call to carry a span that observers created, and the Observer's `ctx` is input-only, so nothing an observer does can reach `Upstream.Do`. `NopObserver` returns `ctx` unchanged; `multiObserver` threads the context through observers in order; the gateway uses the returned context for the rest of the request (`r = r.WithContext(ctx)` in `withRequest`) and for the attempt (`run.ctx` is derived from it). **Default: amend the prep plan's D1 now**, while prep is unimplemented (a one-line signature change in two methods). Fallback if prep has already landed: make the same change as the first, mechanical commit of Phase 11 (touching the metrics observer and the recording test observer). Rejected alternative: an optional side interface found by type assertion; it splits one lifecycle moment across two calls and hides the dependency.
- **D3 Additive event fields (no interface change).** What the prep events cannot express, and what is added to the structs in `observer_events.go`:
  - `RequestStart.TraceHeaders`: copies of the incoming `traceparent` and `tracestate` values only, length-capped (55 and 512 bytes, else dropped), made by the gateway so the observer never sees `Authorization`.
  - `Admission` (and `Rejection` for rate limiting): `RateLimit{Start time.Time, Duration, Outcome}`. Needed for a `rate_limit` span on success; the prep table has a duration on rejections only.
  - `AttemptStart`: `Select{Start, Duration}` (time inside `router.Route`; the scheduler span on success). A failed selection is already a `Rejection` (kind `capacity`/`model`) with a duration.
  - `AttemptEnd`: `NextWorkerUnavailable bool` (a retry was wanted but no other worker existed; the attempt's own response is then served).
  - `FirstToken` and `AttemptEnded` must be called with the **attempt's** context (`run.ctx`, whose values survive cancellation), not `r.Context()`: the gateway keeps the current attempt context on `reqInfo` (one field) for the relay path, which today has only the request context. This is what lets the tracing observer find the attempt span without a map. Documented as part of the Observer contract and pinned by the recording-observer test.
  - Static (non-registry) mode must fire `AttemptStarted`/`AttemptEnded` for its synthetic attempt 1 / worker `"static"` (the code already records it for the request recorder). **Confirm against the prep implementation**; if prep skips static mode, this phase adds it.
- **D4 Outbound trace context goes through a gateway-owned context value, not the Upstream interface.** `gateway.WithTraceRef(ctx, TraceRef{TraceID, Traceparent, Tracestate})` is called by the tracing observer from `AttemptStarted`; `httpUpstream.Do` copies **only** `traceparent` and `tracestate` from it (allow-list, same style as the attempt ID; `Upstream` and its fakes are unchanged). `logRequest` and the attempt log lines add `trace_id` from the same helper (spec §28). With tracing off the helper is absent and nothing changes. A client-supplied `traceparent` is never forwarded as-is.
- **D5 Span model, mapped to Observer events** (all names fixed strings; root and attempts are created from events, with explicit timestamps where the event carries one):

  | Span (kind) | Parent | Started by | Ended by | Notes |
  | --- | --- | --- | --- | --- |
  | `gateway.receive` (SERVER) | remote (trust mode) or none | `RequestStarted` (time from the event) | `RequestCompleted` | status, error code, attempts, model/tenant after `RequestAdmitted`; ends any attempt span still open (panic or missed event). |
  | `rate_limit` | root | `Admission`/`Rejection` with `RateLimit.Start` | same moment, ended at `Start+Duration` | outcome `allowed|rejected|bypassed|unavailable`, limit name, estimated cost. Absent when limiting is off. |
  | `scheduler.select` | root | `AttemptStarted` (success) or `Rejection` kind `capacity`/`model` (failure) | `Select.Start+Duration` | one per attempt; strategy attribute. Registry mode only. |
  | `worker.forward` (CLIENT) | root | `AttemptStarted` | `AttemptEnded` | one **per attempt**, siblings; attributes in D9; its span context is injected as `traceparent`. |
  | `first_token` | the attempt | `AttemptStarted` time | `FirstToken` | streams only. Duration is attempt start to first chunk; `serverflow.ttft_ms` is the request-level TTFT (from request accept, as in the metric and log) so the two numbers are both visible and named. |
  | `completion` | the attempt | `FirstToken` | `AttemptEnded` | streams only: the generation and relay period. A non-stream response has no `first_token`/`completion` (the root and `worker.forward` carry the timing). |
  | `inference`, `queue_wait` | `worker.forward` via `traceparent` | mock worker (D6) | mock worker | not visible to the gateway Observer by construction. |

  Retries: attempt N+1 is a **sibling** `worker.forward` (parent: the root, not the failed attempt), carries a **link** to attempt N's span context (`serverflow.link = retry_of`), and attempt N gets a span event `retry` (attributes: `serverflow.attempt.class`, next attempt number) at `AttemptEnded` when a retry follows. Request ID is on the root and on every gateway span; attempt ID and number on every `worker.forward`. Per-request span state is a small mutex-guarded struct **in the context** (`gwtrace` stores it under its own key), never in a map keyed by request ID, so a missed event cannot leak it. Client disconnect: root status Unset with `serverflow.client_closed=true` (a client leaving is not a server error); 5xx or a failed stream: status Error with the bounded error code as description.
- **D6 Worker side: the mock worker gets `inference` and `queue_wait` spans; the agent and control plane get none.** `handleChat` extracts `traceparent` (the worker's own sampler is `ParentBased(never)`: it records only when the gateway sampled, so an unsampled or untraced request costs ~nothing and a caller that talks to the worker directly cannot make it record unboundedly). `inference` (SERVER) covers the handler; `queue_wait` wraps `engine.Acquire`; a `first_token` span event carries the worker TTFT. Enabled by a new flag `--otlp-endpoint` (empty = off, the default) plus `--trace-insecure-ok` for a non-loopback plaintext endpoint. The worker's request ID and attempt ID attributes are validated (`req_`/`att_` + 16 hex) before use, since a direct caller could send anything.
- **D7 Incoming `traceparent` from clients: default `link`.** `tracing.incoming`: `link` | `ignore` | `trust`. **`link` (default):** the gateway always starts a **new trace** and adds the client's span context as a **link** on `gateway.receive` (IDs only; the client's flags and `tracestate` are not copied). **`ignore`:** no link. **`trust`:** continue the client's trace (parent = remote context, `ParentBased` sampling, `tracestate` forwarded), meant only for a gateway behind a trusted proxy or service mesh. Security reasoning: the gateway is an internet-facing trust boundary. Continuing an untrusted trace lets any client (a) set the sampled flag and force full recording and export cost for every request (sampling amplification), (b) pick trace IDs and graft our spans into someone else's trace or an existing one in the backend, and (c) send oversized or malformed `tracestate`. `link` keeps correlation for a cooperating client without any of these. Malformed headers are ignored, never an error. Incoming `baggage` is never read (D8).
- **D8 Propagation format: W3C Trace Context only (`traceparent`, `tracestate`).** No baggage propagator, no B3. `tracestate` is forwarded to the worker only in `trust` mode.
- **D9 Attribute policy: an allow-list in code, enforced by tests.** All keys are constants in one file (`internal/tracing/attrs.go`); a test fails if any emitted key (span, event, link, resource) is not in the list. *Allowed:* `http.request.method`, `http.route` (the fixed pattern, never the raw path), `http.response.status_code`, `serverflow.request_id`, `serverflow.attempt_id`, `serverflow.attempt` (number), `serverflow.worker_id`, `serverflow.model` (only after the model is confirmed, the same rule as the metrics label), `serverflow.stream`, `serverflow.attempts`, `serverflow.error_code` (bounded enum), `serverflow.attempt.outcome`, `serverflow.attempt.class`, `serverflow.rate_limit.outcome`/`.limit`, `serverflow.est_cost`, `serverflow.scheduler.strategy`, `serverflow.ttft_ms`, `serverflow.client_closed`, worker-side token counts (counts, never text), `queue_ms`, bounded injected-failure mode, and `serverflow.tenant_id` (the opaque `ten_…` ID). *Never:* prompt or response text, messages, any header value (`Authorization`, `User-Agent`, `Cookie`, `X-Forwarded-For`), the API key or any part of it including its prefix, `api_key_id`, tenant **name**, client IP, raw URL or query string, worker address (the worker ID identifies it), error strings from `err.Error()` (they can carry addresses and upstream bodies; only the bounded class/code is recorded and `RecordError` is not used), the client's raw `traceparent`/`tracestate`. `tracing.include_tenant_id` (default true) removes the tenant attribute. Resource: `service.name` (`serverflow-gateway` / `serverflow-mock-worker`), `service.version`, `service.instance.id`; standard `OTEL_*` environment variables are not honoured for sampler or resource, and a test proves `OTEL_EXPORTER_OTLP_HEADERS` set in the environment is not sent.
- **D10 Dependencies: OpenTelemetry Go v1.46.0, and the reasons.** Hand-rolling OTLP, the batch pipeline and W3C parsing is more risk than a dependency (the Phase 8/9 reasoning); the SDK is the maintained standard. **Pin v1.46.0, not the newest v1.47.0, because v1.47.0 sets `go 1.26.0` and would raise the repo floor of 1.25.0.** Direct requires: `go.opentelemetry.io/otel`, `.../otel/trace`, `.../otel/sdk`, `.../otel/exporters/otlp/otlptrace/otlptracehttp`, all `v1.46.0` (verified to exist with `go list -m -versions`; `sdk/trace/tracetest` is inside the sdk module, used by tests). A scratch-module resolution shows about 13 new indirect modules: `go.opentelemetry.io/otel/metric`, `.../otlp/otlptrace`, `go.opentelemetry.io/auto/sdk` v1.2.1, `go.opentelemetry.io/proto/otlp` v1.11.0, `github.com/go-logr/logr` v1.4.4, `github.com/go-logr/stdr` v1.2.2, `github.com/google/uuid` v1.6.0, `github.com/cenkalti/backoff/v5` v5.0.3, `github.com/grpc-ecosystem/grpc-gateway/v2` v2.30.0, `golang.org/x/net`, `google.golang.org/grpc` v1.83.1, two `genproto` modules, and `protobuf` bumped 1.36.11 → 1.36.12. Final versions come from `go mod tidy` and are listed in the PR. Binary size: an OTel-linked scratch binary was 17.6 MB against 8.2 MB for a bare `net/http` server (gateway today: 32.9 MB on darwin/arm64); protobuf and `net/http` are already linked, so the expected increase is under 9 MB; **measured and recorded, not assumed**. The mock worker also grows by about the same amount.
- **D11 Exporter: OTLP/HTTP (protobuf).** Evidence: in the scratch build the gRPC exporter added only ~63 KB and the same 189 packages, because the HTTP exporter's OTLP proto package already links gRPC stubs, so dependency weight does not separate them. HTTP wins on runtime simplicity (plain `net/http`, no long-lived gRPC channel and reconnect logic, easy fake receiver with `httptest`, passes proxies), and the collector and Jaeger both accept it on 4318. gRPC can be added later without touching the observer.
- **D12 Sampling: head-based `TraceIDRatioBased`, default ratio 1.0 when tracing is enabled** (tracing itself is off by default). `trust` mode wraps it in `ParentBased`. **Honestly: head sampling decides before the outcome is known, so "always keep error traces" is impossible at the gateway.** The options are keep-everything (the demo default), a ratio (cheap, drops errors proportionally), or tail sampling in the collector (`tail_sampling` processor, available in the contrib image the repo already pins; a collector config concern, documented but out of this phase). A local "record all, export errors" processor would break cross-process consistency (the worker would have exported its half already) and is rejected. Unsampled requests still get valid trace and span IDs, so `trace_id` is in the logs for every request and `traceparent` is sent with flags `00`.
- **D13 Batching, failure behaviour and shutdown.** SDK `BatchSpanProcessor`: queue 2048, batch 512, delay 5 s, export timeout 5 s, all configurable, **non-blocking** (a full queue drops the span; `WithBlocking` is never used). Exporter retry is enabled but capped at the export timeout, so a dead collector holds the exporter goroutine for at most seconds, not the SDK default of about a minute. Starting with the collector down is **not** a startup error (the exporter does not connect at construction; unlike Redis/Postgres there is no `required` mode). Exporter errors reach one logger that logs the first failure and then at most once per minute plus a recovery line; this uses the SDK's only error hook, `otel.SetErrorHandler`, the single piece of global state (set once in `cmd`, noted in the code). No global tracer provider or propagator is set; both are passed explicitly. Accounting: a processor wrapper counts spans ended and an exporter wrapper counts exported and failed spans, exposed as `tracing_spans_exported_total`, `tracing_spans_dropped_total`, `tracing_export_failures_total` through a small collector in a **new** gateway file registered on the existing registry (no edits to Phase 10's `metrics.go`). **Open point to verify in step 1:** the SDK may not expose queue-drop counts; if exact accounting is not possible the drop counter is `ended − exported − failed` after a flush, labelled in its help text as an estimate while spans are in flight, and the fallback is a ~80-line bounded processor of our own. Shutdown: after `Serve` returns, `Shutdown(ctx)` with a 5 s timeout flushes the queue (a dead collector costs the gateway at most 5 s at exit; documented). The mock worker logs its counts at exit.
- **D14 Configuration: a `tracing` section (file `internal/config/tracing.go`, reserved by the prep split).** Keys: `enabled` (false), `endpoint` (`http://127.0.0.1:4318`), `sample_ratio` (1.0, range 0–1), `incoming` (`link`), `include_tenant_id` (true), `queue_size` (2048), `max_export_batch` (512), `batch_timeout` (5s), `export_timeout` (5s), `allow_insecure_transport` (false). Env: `SERVERFLOW_TRACING_ENABLED`, `_ENDPOINT`, `_SAMPLE_RATIO`, `_INCOMING`, `_INCLUDE_TENANT_ID` (invalid values ignored then validated, like the others). Validation: the endpoint must be an `http(s)` URL with no userinfo and no query (rejected with text that does not echo it); a non-loopback `http://` endpoint is refused unless `allow_insecure_transport` (the Redis/Postgres guard); positive durations and sizes; `enabled: false` skips all validation of the rest. `TracingConfig` gets `String()`, `GoString()`, `LogValue()` and `MarshalJSON()` like `RedisConfig`, even though it holds no secret now, so a later credential field cannot leak by default.
- **D15 Local demo: one standalone file, Jaeger v2.** `observability/tracing/docker-compose.yml` runs `jaegertracing/jaeger:2.22.0` (the tag exists on Docker Hub; Jaeger v2 takes OTLP natively), OTLP/HTTP published on `127.0.0.1:14318` (not 4318, which the unvalidated root compose's collector claims) and the UI on `127.0.0.1:16686`; `make dev-tracing` starts it and prints the config lines; `scripts/trace-demo.sh` sends a request through a local registry-mode cluster with one flaky worker and prints the trace tree from Jaeger's query API. **Hand-off:** Phase 16 moves this into the root compose behind the existing collector; the only gateway-side change is `tracing.endpoint`. The root compose and `observability/otel/` are not edited here.
- **D16 Tests need no Docker.** Layers: (a) in-memory exporter (`tracetest`) for hierarchy, attributes, links and events, with gateway and mock worker in one test binary but **separate tracer providers** and a real HTTP hop, so propagation is genuinely tested; (b) a fake OTLP/HTTP receiver (`httptest`, decoding `ExportTraceServiceRequest`) for the real exporter, batching, flush on shutdown and the failure matrix; (c) the Jaeger demo, manual, on the user's Mac.
- **D17 Overhead budget (targets to be measured, not claims).** Off: no observer registered, no OTel code executed, so the Phase 2 overhead test and the Phase 8 `overhead` benchmark must stay within their run-to-run spread. On, 100% sampled, streaming request with ~8 spans: **added gateway p95 under 1 ms** against the Phase 2 25 ms p95 budget, and a bounded span queue (2048 × ~1 KB ≈ 2 MB). Unsampled: indistinguishable from off within noise (the observer returns early when `!span.IsRecording()` and builds no attribute slices). Reported with allocations per request (`-benchmem`).
- **D18 Documentation:** ADR-017 (or the next free number; prep takes 016) covering D2, D7, D9, D10–D13; `docs/operations/tracing.md`; ARCHITECTURE.md and README updates.

## Proposed Design

```go
// internal/gateway: additions (D2-D4)
type Observer interface {
    RequestStarted(ctx context.Context, e RequestStart) context.Context   // was: no return
    AttemptStarted(ctx context.Context, e AttemptStart) context.Context   // was: no return
    // ... the other five methods unchanged
}
type TraceRef struct{ TraceID, Traceparent, Tracestate string }
func WithTraceRef(ctx context.Context, r TraceRef) context.Context
func TraceRefFrom(ctx context.Context) TraceRef // used by Do (headers) and logRequest (trace_id)

// internal/tracing (core): Setup(cfg, service, instanceID, logger) (*Provider, error)
//   Provider{Tracer, Propagator, Stats() Stats, Shutdown(ctx) error}; Stats has exported/dropped/failed counts
// internal/tracing/gwtrace: New(*tracing.Provider, Options) gateway.Observer
```

Flow in `gwtrace`: `RequestStarted` builds the root (new trace, with a link to the client's span context in `link` mode, or a remote parent in `trust` mode), stores the per-request state struct in the returned context, and sets a `TraceRef` for logs. `AttemptStarted` starts `worker.forward` as a child of the root, adds the retry link, creates the `scheduler.select` span retroactively, injects `traceparent` with the W3C propagator into a temporary header map, and returns a context carrying the attempt span and a `TraceRef`. The remaining events look the span up from the context, set attributes, and end spans. Every method begins with a cheap check (no state in the context, or `!IsRecording()`) and recovers nothing itself (`multiObserver` already recovers panics, prep D3). The mock worker uses the core directly: extract in `handleChat`, start `inference`, wrap `Acquire` in `queue_wait`.

## Acceptance Criteria

1. **Off means off:** with `tracing.enabled=false` (default) every pre-existing test passes unmodified, no OTel code runs on the request path (a test registers no observer and asserts the outbound request has no `traceparent`), and a differential run against master is identical in responses and logs.
2. **Span model:** one streaming request through the gateway and a mock worker yields exactly `gateway.receive` → {`rate_limit`, `scheduler.select`, `worker.forward` → {`inference` → `queue_wait`, `first_token`, `completion`}} with correct parent/child IDs, kinds, and timestamps that nest (children inside parents) when measured in one process; one trace ID across both processes.
3. **Propagation:** the worker receives `traceparent` whose parent span ID is the gateway's `worker.forward` span ID and whose sampled flag equals the gateway's decision; flags `00` when unsampled; `tracestate` absent unless `trust`. The worker never sees a client-supplied `traceparent` verbatim.
4. **Retry shape:** with the first worker failing (503 or dropped connection) and a second succeeding: one root, two `worker.forward` siblings, the second linked to the first, a `retry` event with the class on the first, two `scheduler.select`, both attempt IDs and worker IDs present, `serverflow.attempts=2`, and the worker spans parented to the matching attempt.
5. **Incoming policy:** `link`: new trace ID, link to the client's span context, client flags and `tracestate` not copied; `ignore`: no link; `trust`: same trace ID, parent = client span; malformed, oversized and duplicated headers are ignored with a normal response; a client with sampled=1 does not force recording in `link`/`ignore` when the ratio is 0.
6. **Failure and edge shapes:** auth refusal, rate-limit refusal (429), unknown model, no capacity, client disconnect (499), worker midstream failure, and a handler panic each produce a root span that is ended exactly once with the right status; no span is left open (a leak check counts started minus ended spans across all of these, with `-race`).
7. **No secrets (canary test):** requests carry canary strings in the prompt, API key, `Authorization`, `User-Agent`, `X-Forwarded-For`, query string, tenant name, client `tracestate` and a worker error body; the full JSON dump of all spans from both processes (names, attributes, events, links, status descriptions, resource) contains none of them. An allow-list test fails on any attribute key not in `attrs.go`. `OTEL_EXPORTER_OTLP_HEADERS` in the environment is not sent.
8. **Bounded attributes:** every string attribute has a fixed or validated vocabulary or length (request/attempt IDs match their format; error codes and classes come from the existing constant sets); a request with a 1 MiB model name or a hostile `traceparent` adds no unbounded value to any span.
9. **Collector failure matrix:** fake receiver returning 500, closed port, black-holed connection, and slow responses: request latency and status are unchanged (p95 within noise of tracing-off), the queue stays at or below `queue_size`, the drop and failure counters move, error logging is rate-limited (at most one line per minute plus recovery), recovery is automatic and later spans arrive, and no goroutine or connection leaks after shutdown.
10. **Shutdown flush:** a clean shutdown exports the spans still queued within `export_timeout`; with the receiver dead, shutdown returns within 5 s plus a small bound; the request path never blocks on the exporter (tested with a receiver that hangs forever).
11. **Metrics:** `tracing_spans_exported_total`, `tracing_spans_dropped_total` and `tracing_export_failures_total` appear on `/metrics` only when tracing is enabled; no label carries a request-derived value.
12. **Config:** defaults, env overrides, range checks (`sample_ratio`), the insecure-endpoint refusal, userinfo and query rejection, redaction in `String`/`LogValue`/JSON, and "disabled skips validation" are each tested; invalid text never echoes the endpoint.
13. **Logs:** with tracing on, the request log, attempt log and mock-worker `chat` log carry the same `trace_id` as the spans (spec §28), for sampled and unsampled requests; absent when off.
14. **Dependencies:** `go.mod` keeps `go 1.25.0`; the OTel modules are exactly D10 (v1.46.0); `go mod tidy -diff` is empty; `go list -deps ./internal/gateway` contains no `go.opentelemetry.io` package; `govulncheck` is clean; binary sizes before and after are recorded.
15. **Overhead:** D17 numbers measured on this machine with the Phase 2 overhead test and an opt-in benchmark, tracing off, unsampled and 100% sampled, recorded in the benchmark note with spread and allocations; added p95 at 100% below 1 ms, or the shortfall is reported and discussed rather than hidden.
16. **Real collector demo (manual, user's Mac):** `make dev-tracing`, then `scripts/trace-demo.sh`; Jaeger shows the D5 tree for a successful request and the retry shape for a flaky-worker request, searchable by `serverflow.request_id`. Recorded with the commands used.
17. `gofmt`, `go vet`, `go build`, `go test -race ./...`, `golangci-lint run ./...`, `scripts/quality.sh full` pass; CI jobs need no Docker for tracing tests.

## Risks

- **Context propagation through the streaming relay.** Spans and `TraceRef` ride on contexts, and the relay path currently only has the request context (D3). A wrong context silently parents `first_token`/`completion` to the wrong span or loses the `traceparent`. Mitigated by passing the attempt context explicitly, the recording-observer contract test, and mutation tests on exactly this.
- **Span leaks on client disconnect or panic.** A missed `End` leaks memory and leaves an unfinished span. Per-request state lives in the context (collected with the request), `RequestCompleted` ends leftovers, and the leak-count test runs every failure shape. A panicking observer is contained by `multiObserver`, but a panic inside `gwtrace` could skip an `End`; its methods are written to do the `End` first.
- **High-cardinality or hostile attributes.** Traces tolerate more cardinality than metrics, but backends still bill and index. Mitigated by the allow-list, validated IDs, and the model rule; `tenant_id` is the one high-cardinality key and is switchable.
- **Dependency weight and the Go floor.** About 13 new modules and a larger binary; Dependabot will propose v1.47+, which needs Go 1.26. The decision then is to pin or to raise the floor deliberately; do not merge it unexamined.
- **Attacker-controlled trace headers.** Covered by D7/D8 (link by default, no baggage, length caps). `trust` mode re-opens sampling amplification and is documented as such.
- **Seam coupling.** D2/D3 change the prep plan's interface and event structs; Phases 10 and 12 also edit these files. The changes are additive apart from the two return types, and the prep plan should be amended before it is built.
- **Clock skew across processes.** Each process stamps its own wall-clock time; a worker clock ahead or behind makes a child appear to start before its parent. The local demo shares a clock. Durations within a process are unaffected; backends can adjust. Documented, not corrected.
- **A collector outage is invisible to the client but not to operators.** Mitigated by the counters, the rate-limited log line and the 5 s shutdown bound; there is no alert until Phase 10.
- **Exit delay.** A dead collector can add up to 5 s to a shutdown; the drain timeout in orchestration must allow it.
- **Unverified demo.** The Docker path is checked only by the user (see Verification Plan).
