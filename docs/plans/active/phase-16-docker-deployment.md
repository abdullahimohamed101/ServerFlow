## Outcome

`make dev-up` brings up the whole system on one machine from a clean checkout, and `make dev-smoke` proves it works end to end with real requests: a gateway in front of three mock workers of different speeds, each with its own worker agent, registered with a control plane; API-key authentication and Redis rate limits backed by PostgreSQL and Redis; lifecycle events flowing through Redpanda into usage rows by the usage consumer; Prometheus and Grafana with the committed dashboards; traces in Jaeger. All of it runs as non-root, read-only, capability-free containers on a private network, with only the gateway and the UIs published on `127.0.0.1`, no secret committed, and nothing left behind after `make dev-down`.

```text
host 127.0.0.1 only:  gateway/lb :18080   control plane :19090   Prometheus :19091   Grafana :13000   Jaeger UI :16686
                          |                    |                      |                  |                 |
 edge network (published services) ------------+----------------------+------------------+-----------------+
 backend network (internal: true, no egress)
   gateway x N --> control plane <-- worker-agent-1..3 --> mock-worker-1..3 (100 / 60 / 20 tok/s)
      |  |  |--> postgres (keys, usage)  redis (quotas)  redpanda (events) --> usage-consumer --> postgres
      |  +-----> jaeger (OTLP/HTTP)            prometheus --scrapes--> gateway, control plane, mock workers --> grafana
   one-shot jobs: migrate, redpanda-init        scripts: dev-up (secrets, preflight, bootstrap), dev-smoke
```

Acceptance headline (spec §58): *control plane, mock workers, redis, kafka, postgres, prometheus, grafana, otel, one-command dev-up.* Everything that can be checked without Docker is checked in CI by Go tests and linters; the end-to-end claim is checked by the compose smoke job, which must run, not skip (D26).

## Non-Goals

- No production hardening, TLS termination, secrets manager, image signing, multi-host or multi-node deployment, autoscaling or HA data stores. One Redpanda broker, one PostgreSQL, one Redis, one Prometheus.
- No Kubernetes manifests or Helm (Phase 17). No real vLLM worker or GPU (Phases 13, 18). No change to scheduling, retry, rate-limit, auth, event or metric behaviour.
- No published images or registry push (Phase 17 decides the registry). No SBOM, signing or provenance (D23 defers them with reasons).
- No runtime control API for mock workers; failure injection is by start-up flags and container operations (D18).
- No Alertmanager, no OpenTelemetry Collector (ADR-018 sends OTLP straight to Jaeger v2; the Phase 0 collector skeleton is deleted, D20).
- No native Windows support for `dev-up` (bash scripts; WSL2 is fine). Windows still builds and tests the Go code as today.

## Current Architecture

- **Binaries** (`cmd/`): `gateway` (`-config`, env; `:8080` data port plus a separate metrics listener), `control-plane` (`-config`, env; API `127.0.0.1:9090`, token-protected, metrics `127.0.0.1:9101`), `worker-agent` (`-config`, env; **no HTTP server**), `mock-worker` (**flags only**, no env overlay; `/health /readyz /v1/models /stats /metrics` and chat on `--addr`, default `127.0.0.1:9000`), `usage-consumer` (`-config`, env; `/healthz` and `/metrics` on `events.consumer.metrics_addr`, default `127.0.0.1:9103`, loopback enforced unless `events.allow_insecure_transport`), `admin` (`migrate up|status`, `tenant create`, `key create` prints the key once on stdout, `usage summary`; migrations are `go:embed`ded), `benchmark` (host tool). `/healthz` exists on gateway, control plane and consumer; `/readyz` on gateway (in registry mode 503 until the registry has a worker), control plane and mock worker.
- **Configuration** (`internal/config`): defaults, optional YAML, then `SERVERFLOW_*` environment (spec §50). Unparsable values are ignored silently. Every non-loopback connection has a guard: PostgreSQL DSN without TLS needs `SERVERFLOW_POSTGRES_ALLOW_INSECURE_TRANSPORT`, Redis `SERVERFLOW_REDIS_ALLOW_INSECURE_TRANSPORT`, Kafka `SERVERFLOW_EVENTS_ALLOW_INSECURE_TRANSPORT` (not needed with SCRAM), a non-loopback `metrics.listen` needs `metrics.token` (at least 16 characters) or `allow_non_loopback`, a non-loopback `control_plane.addr` needs `control_plane.token`.
- **Existing compose assets.** Root `docker-compose.yml`: an unvalidated Phase 0 skeleton (Redis, Postgres with password `postgres`, bitnami Kafka, Prometheus and Grafana on host `9090`/`3000`, an OTel collector; no ServerFlow image). `observability/docker-compose.yml` (Phase 10): Prometheus and Grafana for **host** processes, `127.0.0.1:9091`/`3000`, `host.docker.internal` targets. `observability/tracing/docker-compose.yml` (Phase 11): Jaeger v2. `scripts/dev-{postgres,redis,kafka}.sh`: throwaway servers with fixed public passwords for tests. `make dev-cluster`: the same cluster as host processes.
- **No Dockerfile, no `.dockerignore`, no image of any ServerFlow binary exists.** `.gitignore` already ignores `.env`, `.env.*` (except `.env.example`), `*.key`.
- **Prometheus** (`observability/prometheus/prometheus.yml`): three jobs (`serverflow-gateway`, `-control-plane`, `-mock-worker`) selecting `file_sd` groups by a `component` label; the bearer-token `authorization` block is commented out.

## Decisions (confirm before implementation)

### Images

- **D1. One multi-stage `deploy/docker/Dockerfile`, one build stage, one final target per image.** A single `build` stage compiles `gateway control-plane worker-agent mock-worker usage-consumer admin healthcheck` (one `go mod download` layer, one compile); targets `gateway`, `control-plane`, `worker-agent`, `mock-worker`, `usage-consumer`, `admin` each copy their binary plus `healthcheck` onto the runtime base. Context is the repository root (`docker build -f deploy/docker/Dockerfile .`). Rejected: one Dockerfile per binary (seven copies of the same pins). No `benchmark` image: the harness runs from the host as in Phase 10 (YAGNI; add when Phase 15 needs it in-network). Images are named `serverflow/<name>:${SF_TAG:-dev}`, built by compose, never pulled.
- **D2. Base images pinned by tag and digest, literal in `FROM` lines.** Builder `public.ecr.aws/docker/library/golang:1.26.9@sha256:d7722066f0b60ceccb6c0643cbed1f5f9e15506ac237146c95333504d7805d89` (Docker Hub is avoided because it rate-limits shared runners, `docs/development/ci.md`); runtime `gcr.io/distroless/static-debian13:nonroot@sha256:e2e927ec666bae08560abb3c55d0659eceabb657f56b6782ab500a9fc7f555e3`. Literal references (no `FROM ${ARG}`) keep hadolint's DL3006 and Dependabot's `docker` ecosystem working. The Go version follows `go.mod`'s floor policy (1.26) at the newest patch; bumping it is a Dependabot PR plus a digest refresh.
- **D3. Static, stamped, reproducible binaries.** `CGO_ENABLED=0`, `-trimpath`, `-buildvcs=false`, `-ldflags="-s -w -buildid= -X <pkg>.Version=$VERSION -X <pkg>.Commit=$COMMIT"`. Build args `VERSION` (default `dev`) and `COMMIT` (default `unknown`) are set by `make dev-up` from `git describe --always --dirty` and `git rev-parse HEAD`. Because `-buildvcs=false` and no `.git` in the context remove the VCS data `serverflow_build_info` and the tracing service version read today, **W2** adds package variables they prefer over `debug.ReadBuildInfo`. Claim: identical inputs give identical binaries (tested); image layers are not claimed byte-identical.
- **D4. Runtime hardening.** Distroless static, user `65532:65532`, no shell, no package manager; exec-form `ENTRYPOINT`; `EXPOSE` documents ports; no `ENV` with secrets and no `VOLUME`; OCI labels (`source`, `revision`, `version`). Compose adds `read_only: true`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, `pids_limit`, no `privileged`, no `network_mode: host`, no Docker socket mount. Third-party services get the same flags with the recipes verified above (tmpfs data directories, explicit `user:`); the exception list (a service that cannot run read-only) must be empty, and a test fails if one is added silently.
- **D5. Health checks.** Add `cmd/healthcheck` (**W4**): standard library only, one argument, a URL whose host must be loopback, 3 s timeout, no redirects, exit 0 only for 2xx; tested like any command. It is copied into every ServerFlow image because distroless has no shell, `curl` or `wget`. Checks live in compose (`healthcheck:`), not in the Dockerfile, so Kubernetes and other runtimes are unaffected and intervals are tunable: gateway `GET /healthz`, control plane `/healthz`, mock worker `/readyz`, usage consumer `/healthz` on its loopback metrics address (works because the probe runs inside the container). **The worker agent has no HTTP endpoint and gets none in this phase**: its compose healthcheck is disabled, `restart: on-failure:5` covers crashes, and registration and heartbeat are asserted through the control plane's metrics by `dev-smoke` and visible as `worker_heartbeat_age_seconds`. Phase 17 needs a liveness signal for the agent and decides how (D29). Gateway health is `/healthz`, not `/readyz`, so the gateway is "healthy" before any worker registers; readiness is what `dev-smoke` waits for. Third-party checks use what their images contain: `pg_isready -h 127.0.0.1`, `redis-cli ping` (password through `REDISCLI_AUTH`), `rpk cluster health`, `wget -q -O /dev/null`.
- **D6. Builder compatibility.** The Dockerfile uses only syntax the classic builder and BuildKit both accept (no `--mount=type=cache`, no `$BUILDPLATFORM`, no heredocs, no `# syntax` line). Cost, measured: no Go build cache between builds (42 s warm rebuild here). Alternative, rejected as default: require `buildx` (`brew install docker-buildx`) for cache mounts. `dev-up` prints the builder in use; CI uses BuildKit through the runner's buildx on the same Dockerfile. Native builds only (the engine's architecture); multi-arch publishing is Phase 17's problem.
- **D7. `.dockerignore` at the repository root** (the classic builder reads only that one): `.git .github .agents .claude .zed .data .dev .env .env.* !.env.example docs observability benchmark bin **/*_test.go *.md`. The context was 3.9 MB in the experiment. A test asserts it excludes `.env`, `.dev` and `.git`.
- **D8. Resources, restarts, logs.** Memory limits (`mem_limit`) sized for a 4 GB VM: gateway 128 MB (each replica), control plane 64, agents 32, mock workers 64, consumer 64, Postgres 256, Redis 64, Redpanda 768 (`--memory 512M --smp 1`), Prometheus 256, Grafana 256, Jaeger 256; Go services also get `GOMEMLIMIT` at about 80% of the limit; `cpus` unset (a 2-CPU VM cannot be partitioned usefully). Total limits are about 2.4 GB, expected idle use about 1.2 GB (to be measured, AC 20). `restart: on-failure:5` for long-running services, `"no"` for jobs. Logging `json-file` with `max-size: 10m`, `max-file: 3` through one YAML anchor. `stop_grace_period: 40s` for the gateway (its `shutdown_timeout` is 30 s plus event flush) and 15 s elsewhere; exec-form entrypoints make the Go process PID 1 and it handles SIGTERM.

### Compose topology

- **D10. One root `docker-compose.yml` replaces the skeleton** (spec §48 puts it at the root). Project name `serverflow-dev` (`COMPOSE_PROJECT_NAME` overrides it so two worktrees can run side by side); no `container_name`. Minimum Compose 2.24 (`required: false` dependencies, optional `env_file`), checked by `dev-up`. `include:` is not used.
- **D11. Profiles.** `core`: control-plane, mock-worker-1..3, worker-agent-1..3, gateway. `data`: postgres, redis, migrate. `events`: redpanda, redpanda-init, usage-consumer. `observability`: prometheus, grafana. `tracing`: jaeger. `scale`: lb (nginx), added automatically when `GATEWAYS` is greater than 1. `make dev-up` activates `core,data,events,observability,tracing` (everything but `scale`); `PROFILES=core make dev-up` is the minimum. The gateway's features follow the active profiles through variables the script writes to `.env.profile` (`SF_AUTH_MODE`, `SF_RATE_LIMIT_MODE`, `SF_EVENTS_MODE`, `SF_TRACING_ENABLED`): without `data` the gateway runs `auth.mode=off` and `rate_limit.mode=off` (it logs that auth is off), without `events` `events.mode=off`, without `tracing` `tracing.enabled=false`. Dependencies on optional services use `required: false`. `dev-smoke` asserts what the active profiles provide and prints each check it did not run as SKIPPED; the CI job uses all profiles and fails on any skip (D26).
- **D12. Start-up ordering by health.** `postgres` (healthy) -> `migrate` (admin `migrate up`, `service_completed_successfully`) -> gateway (`auth.mode=required` refuses an unmigrated database) and usage-consumer; `redis` healthy -> gateway; `redpanda` healthy -> `redpanda-init` (creates the SCRAM user and topic `inference.lifecycle.v1` with 6 partitions, idempotently, using the same image's `rpk`) -> gateway events and consumer; `control-plane` healthy -> agents and gateway; `mock-worker-n` healthy -> `worker-agent-n`; Jaeger and Prometheus are not dependencies of anything (tracing and metrics must never gate requests). `docker compose up -d --wait --wait-timeout 180`. The gateway's events producer survives a broker that is not up yet, so the broker dependency is for tidy logs, not correctness.
- **D13. Secrets and bootstrap, without committing or printing anything.** `scripts/dev-up.sh` (Bash) does, in order: tool and version preflight; validates `.env` (D14); creates `.dev/` (mode 0700, gitignored) on first run with `secrets.env` (0600: Postgres password and DSN, Redis password, Redpanda SCRAM password, control-plane token, metrics token, Grafana admin password; 32+ hex characters read from `/dev/urandom`, never echoed) and `metrics_token` (0644 inside the 0700 directory, because the Prometheus container runs as `nobody` and compose cannot set a bind-mounted file's mode); builds and starts; creates, idempotently, tenants `dev` (generous quota) and `limited` (`--rpm 3`) with `admin tenant create`, and writes their keys to `.dev/api_key` and `.dev/api_key_limited` (0600) by capturing the one stdout line of `admin key create` into the file without passing it through the terminal or logs; prints only URLs and file paths. Services receive secrets only through `env_file: .dev/secrets.env` (never interpolated into `environment:`, because `docker compose config` prints those). Generated passwords are hex only, so they are safe inside a DSN. A user-supplied value in `.env` for a secret is refused rather than escaped. `dev-reset` deletes `.dev/`. No default password is committed anywhere (the old root compose's `postgres/postgres` and `admin` die with the skeleton); `.env.example` contains no secret.
- **D14. `.env` is configuration, validated as hostile input.** `.env.example` (committed) holds host ports, `GATEWAYS`, `PROFILES`, the mock-worker knobs (D18), `SF_STRATEGY`, image overrides and retention. `dev-up.sh` accepts values only from `[A-Za-z0-9._:/@-]` (no `$`, quotes, spaces, newlines or `=`), ports in 1024-65535 and unique, integers in range, profile names from the known set; anything else aborts naming the variable and printing no value. Mock-worker flags are passed as separate list elements in `command:` (never one shell string), so a value cannot add a flag. A Go test runs the script's `--check-env FILE` mode (no Docker) against hostile files.
- **D15. Networks and ports.** `backend`: `internal: true`, every service, so data stores and workers have no route to the internet and none is published. `edge`: an ordinary network joined only by services that publish a port (gateway or lb, control plane, Prometheus, Grafana, Jaeger UI). Every `ports:` entry is `127.0.0.1:${X_PORT}:port`; a test fails any other form. Defaults avoid the collisions seen on this machine (3000, 5433, 8000 held by another project; 9090 by the control plane): gateway `18080`, control plane `19090`, Prometheus `19091`, Grafana `13000`, Jaeger UI `16686` (the Phase 11 default); all are `.env` variables (`GATEWAY_PORT`, `CONTROL_PLANE_PORT`, `PROMETHEUS_PORT`, `GRAFANA_PORT`, `JAEGER_UI_PORT`). Postgres, Redis, Redpanda, the OTLP port and all metrics listeners are not published; `make dev-psql`, `dev-redis-cli`, `dev-rpk` exec into the containers. `dev-up` checks each host port is free before starting and names the variable to change. The control plane is published on loopback (token-protected) because `cmd/benchmark --control-plane` and operators need it from the host; set `CONTROL_PLANE_PORT=` empty to unpublish. Phase 10's `observability/docker-compose.yml` keeps `9091`/`3000` for host-process mode, so the two stacks no longer collide on the control plane's `9090`.
- **D16. Metrics listeners inside containers: bind `0.0.0.0` with a bearer token, not `allow_non_loopback`.** The gateway and control plane run `SERVERFLOW_METRICS_LISTEN=0.0.0.0:9100` / `:9101` and `SERVERFLOW_METRICS_TOKEN` (the shared `metrics_token`), so the config guard stays on and the request path it protects is the same one production would use. The ports are reachable only on `backend`. Prometheus presents the token from `/etc/prometheus/secrets/metrics_token`. Mock workers serve `/metrics` unauthenticated on their service port (a test double, same as Phase 10) and the consumer's metrics stay on loopback inside its container (not scraped; its health is in D5). Residual risk, stated: any container on `backend` can read mock-worker metrics.
- **D17. Prometheus config.** A second file `observability/prometheus/prometheus.compose.yml`: the same job names, `relabel_configs`, `sample_limit`, `rule_files` and `global` as `prometheus.yml`, with the gateway and control-plane jobs adding `authorization: {type: Bearer, credentials_file: /etc/prometheus/secrets/metrics_token}`, and the gateway job using `dns_sd_configs: [{names: [gateway], type: A, port: 9100}]` so `--scale gateway=N` is scraped without edits. `observability/prometheus/targets/compose.yml` lists control plane, mock workers (`worker_id: mock-1..3`, equal to the agents' `SERVERFLOW_WORKER_ID` so worker-side and registry series join) by service name. Phase 10's `prometheus.yml` and `targets/local.yml` are unchanged (a shared file cannot have the token for one stack and none for the other: a missing credentials file is a scrape error). Only `compose.yml` of `targets/` and the rules directory are mounted, so `host.docker.internal` targets never appear. A Go test fails if the two configs' job names, relabelling or rule files drift. `quality.sh observability` also runs `promtool check config --syntax-only` on the compose config. `file_sd` for fixed services plus `dns_sd` for the scalable gateway; Prometheus retention 2 d, read-only root, tmpfs `/prometheus`.
- **D18. Mock workers and failure injection.** Three workers as in `make dev-cluster`: `mock-1` 100 tok/s TTFT 100ms, `mock-2` 60 / 150ms, `mock-3` 20 / 300ms, model `mock-model`, `--max-concurrency` and `--queue-size` from `WORKER_CONCURRENCY` (8) and `WORKER_QUEUE` (64) (the Phase 10 sizing lesson). Each worker's knobs are `.env` variables passed as flags: `MOCK_n_TTFT`, `MOCK_n_TPS`, `MOCK_n_FAILURE_RATE` (0), `MOCK_n_FAILURE_MODE` (`error|unavailable|drop|midstream`), `MOCK_n_STARTUP_DELAY`, `MOCK_n_SEED`; changing one and `make dev-up` recreates only that worker. Chaos operations are plain compose commands, documented with the measured behaviour: `docker compose kill mock-worker-3` (stays down: `on-failure` does not restart a `kill`, verified), `docker compose start`, `docker compose pause`, `docker network disconnect`, and `stop worker-agent-3` (heartbeat loss while the worker still serves). No runtime control endpoint is added; if Phase 15 needs one it adds it to the mock worker. Agents are separate containers from their workers (own network namespace); Phase 17's pods put them together.
- **D19. Persistence.** Default is **ephemeral**: every data directory is a size-capped tmpfs (Postgres 256 MB `uid=70`, Redis 64 MB, Redpanda 512 MB `uid=101`, Prometheus 512 MB, Grafana 64 MB, Jaeger in memory), so `dev-down` leaves no volume and there are no anonymous volumes (every image `VOLUME` path is covered; a Docker-requiring test lists mounts of all containers and fails on an unnamed volume). `PERSIST=1` adds `docker-compose.persist.yml`, which replaces the tmpfs entries with explicitly named volumes; `dev-down` keeps them, `dev-reset` removes them (`down -v`). Data lost on `dev-down` by default: keys (regenerated and re-bootstrapped by the next `dev-up`), usage rows, metrics.
- **D20. What is retired and what stays.** Root `docker-compose.yml` is replaced (Kafka becomes Redpanda per ADR-019; nothing of the skeleton survives). `observability/otel/otel-collector.yml` and the compose collector are deleted (unused since ADR-018). `observability/docker-compose.yml` (`make obs-up`) and `observability/tracing/docker-compose.yml` (`make dev-tracing`) stay: they serve host-process development (`make dev-cluster`, `scripts/trace-demo.sh`), and their docs gain one line pointing to `make dev-up` for the containerised stack; their stale statements about the root compose (observability.md "unvalidated and Phase 16's to reconcile", tracing.md "Phase 16 moves it") are corrected. `make dev-cluster`, `dev-postgres`, `dev-redis`, `dev-kafka` and their scripts (tests depend on them) stay unchanged.
- **D21. Tracing in compose.** Jaeger v2 in profile `tracing`, OTLP/HTTP `http://jaeger:4318` on `backend`, UI published on loopback. Gateway: `SERVERFLOW_TRACING_ENABLED=true`, `SERVERFLOW_TRACING_ENDPOINT`, `SERVERFLOW_TRACING_SAMPLE_RATIO=1.0` (dev; `.env` overrides), `SERVERFLOW_TRACING_ALLOW_INSECURE_TRANSPORT=true` (**W3**); mock workers `--otlp-endpoint=http://jaeger:4318 --trace-insecure-ok`. Traces are in memory only (documented).
- **D22. Grafana.** Provisioning and dashboards are mounted read-only from `observability/grafana/` unchanged; `PROMETHEUS_URL=http://prometheus:9090`; admin password from `secrets.env`; anonymous access, sign-up, analytics and update checks off; read-only root, tmpfs `/var/lib/grafana` (`uid=472`) and `/tmp`.
- **D23. Security posture and scanning.** Throwaway generated secrets, never in git, images, logs or terminal; `docker inspect` of a container shows its environment to whoever can reach the Docker socket, which is the same trust boundary as the developer's machine (documented). Scanning: **Trivy** over the six ServerFlow images in the nightly workflow, report-only for HIGH and CRITICAL with `--ignore-unfixed`, run from `ghcr.io/aquasecurity/trivy` pinned by digest (also on `public.ecr.aws`). Honest cost: its vulnerability database is a separate anonymous download that is known to be rate limited, so it is advisory and never gates a pull request; `govulncheck` (already gating) covers Go dependencies and distroless has almost no OS surface. SBOM, signing and provenance are deferred to the registry decision in Phase 17. Third-party images are not scanned by us. `docker/compose` dependencies and `docker` base images join Dependabot (`package-ecosystem: docker` for `deploy/docker`, `docker-compose` for the root; whether Dependabot reads the ECR/GCR/quay references is unverified and listed in Risks).

### Workflow

- **D24. Commands.** `make dev-up` (alias for `scripts/dev-up.sh up`), `dev-down` (`down --remove-orphans`, keeps persistent volumes), `dev-reset` (`down -v --remove-orphans`, deletes `.dev/` and the built `serverflow/*:dev` images only), `dev-smoke`, `dev-ps`, `dev-logs [SERVICE=]`, `dev-config` (`docker compose config --no-env-resolution`, safe to paste), `dev-pull`, `dev-psql`, `dev-redis-cli`, `dev-rpk`, `dev-key` (prints the path of the key file and the `export SF_KEY=$(cat ...)` line, not the key). `dev-up` is idempotent and exits non-zero with a one-line cause on the first failure; with `--wait` timeouts it prints `docker compose ps` and the last 20 log lines of unhealthy services (logs contain no secrets, AC 9). `GATEWAYS=3 make dev-up` scales the gateway.
- **D25. `dev-smoke` assertions (each prints `PASS`/`FAIL`/`SKIPPED name`; the last line is `smoke: P of N checks passed, F failed, S skipped`; it exits non-zero on any failure).** S1 gateway `/readyz` is 200 within 60 s and `/v1/models` with the key lists `mock-model`. S2 a request without a key is 401 `invalid_api_key`-class, with a bad key 401. S3 a non-streaming chat completion is 200 with `choices` and `usage`. S4 a streaming completion yields at least two `data:` chunks and ends with `[DONE]`. S5 24 requests spread over at least two workers (read from `scheduler_selections_total` in Prometheus after a scrape). S6 the `limited` tenant gets 429 with `Retry-After` on its fourth request in a minute. S7 Prometheus reports gateway, control plane and the three mock workers `up`, and `inference_requests_total` is non-zero. S8 Grafana health is ok and the four dashboards (`sf-cluster-overview`, `sf-worker`, `sf-scheduler`, `sf-model`) exist (basic auth from the secrets file through a curl config on stdin, never on a command line). S9 within 60 s `admin usage summary --tenant dev` shows the requests (Kafka to Postgres). S10 Jaeger returns a trace containing both gateway and mock-worker spans. S11 failover: `kill mock-worker-3`; within 30 s the registry reports it not healthy while requests keep returning 200; `start` it and it is healthy again within 30 s (spec §67 steps 7-8). S12 no generated secret value appears in `docker compose logs` (each value is searched, none printed). With `GATEWAYS>1`: S13 requests reach at least two gateway instances and the `limited` tenant's quota is shared (total admitted across all replicas does not exceed quota plus burst: the Phase 8 shared-quota demonstration through real processes). Smoke never prints a key, token or password and uses throwaway tenants only.
- **D26. CI.** Two jobs in `ci.yml`. (a) `deploy (lint, config, static tests)`, every pull request, about 2 min, no Docker pulls: pinned `hadolint` release (v2.15.1 binary, SHA-256 from its `checksums.sha256`, as promtool is verified), `docker compose config --no-env-resolution -q` for the default, `PERSIST=1` and all-profiles combinations using a fixture env, and the named `tests/deploy` Go tests, which **must run** (the `quality.sh deploy` stanza greps for each test name like `must_run`). (b) `compose smoke`, every pull request and `push` to master plus the nightly workflow: pulls with retries (D9), builds with the runner's BuildKit, `make dev-up`, `make dev-smoke`, then on failure uploads `docker compose logs` (secret-free, AC 9) and in an `if: always()` step `make dev-down` and the leak check (AC 5). The job fails unless the smoke's last line says `0 failed, 0 skipped`. Time budget 25 min; expected 6-10 min on a 4-vCPU runner (build about 1.5 min, pulls about 1-2 min, start about 30 s, smoke about 2 min); this is an estimate, measured at implementation (AC 19). The nightly run adds `GATEWAYS=3` (S13) and the Trivy report. **Required or advisory:** advisory in the first weeks (not in the owner's required-check list in `docs/development/ci.md`), proposed as required after ten consecutive green runs on master; the owner changes branch protection. Not path-filtered: a filtered required check that never runs blocks merges. Images and the compose file are not published from CI.
- **D27. Documentation.** `README.md` quick start (needs only Docker with Compose 2.24+, `git`, `make`, `curl`, `bash`; the commands in it are executed by the verifier from a clean clone), `docs/operations/docker-deployment.md` (topology, ports, profiles, env reference, persistence, scaling, chaos operations, troubleshooting: port collision, Colima mounts, disk, pull limits, `dev-reset`), ADR-020 (D1-D9, D13, D16, D19, W1: Dockerfile strategy, base images and sources, ephemeral default, secrets, the metrics-token choice, the insecure-transport knob), updates to `docs/development/ci.md` (the two jobs, the corrected Redpanda-source finding, the pull helper), `docs/operations/observability.md` and `tracing.md` (D20), `ARCHITECTURE.md` (deployment paragraph; the line "Docker Compose skeleton is unvalidated" removed), and the README phase table.
- **D28. Gateway scaling and what fronts it.** `GATEWAYS=N` runs N gateway replicas on `backend`. With N greater than 1 the `scale` profile adds `lb`: `nginx-unprivileged` (D9) with a 20-line `deploy/compose/nginx.conf` (`resolver 127.0.0.11 valid=2s`, variable `proxy_pass http://gateway:8080`, `proxy_buffering off`, `proxy_http_version 1.1`, long read timeout for SSE), published instead of the gateway. With N equal to 1 nothing sits in front and the gateway publishes directly. Evidence for choosing nginx over writing a proxy (a dependency we would own) or using a published port range (clients would have to balance themselves): it ran hardened and spread requests across three replicas (5/5/2 of 12). Rejected: Traefik and Envoy (larger, more configuration for the same job), HAProxy (equal, but nginx's unprivileged image is published by the vendor on ECR). Prometheus finds replicas by DNS (D17). Streaming through the lb is covered by S4 when N>1.
- **D29. Phase 17 hand-off.** Kubernetes reuses the six images, the `healthcheck` binary (as exec probes), the Prometheus rules and dashboards, and the env variable names in this plan's env reference (`docker-deployment.md`). Phase 17 must decide: how the worker agent proves liveness (an HTTP endpoint on the agent, or an exec probe on a heartbeat marker), the registry and tags for the images, TLS for the control-plane token path (W1's knob is a dev affordance), secrets via Kubernetes Secrets rather than `env_file`, and metrics scraping with ServiceMonitors instead of `dns_sd`. Phase 15's chaos runs use D18 as is.
- **D30. Out of scope, stated once.** Production hardening (TLS everywhere, network policies, image signing, secret rotation), multi-host Compose or Swarm, resource tuning for real load, persistent data stores as a supported mode beyond `PERSIST=1`, a UI for key management, Windows-native scripts.

### Work items outside `deploy/` (small code changes this phase needs; each gets tests)

- **W1. `control_plane.allow_insecure_transport`** (env `SERVERFLOW_CONTROL_PLANE_ALLOW_INSECURE_TRANSPORT`, default false): relaxes the two existing "token over plain http" guards (`gateway.control_plane_url` in `internal/config/gateway.go`, `worker.control_plane_url` in `internal/config/worker.go`) the same way `postgres/redis/events/tracing.allow_insecure_transport` do. Without it, no container can talk to the control plane, which must listen non-loopback and therefore must have a token (verified). - **W3. `SERVERFLOW_TRACING_ALLOW_INSECURE_TRANSPORT`** (the YAML key exists; the env overlay does not).
- **W4. `cmd/healthcheck`** (D5).
- **Checked, no gap:** every other variable compose sets exists in `applyEnv` (`GATEWAY_*`, `SCHEDULER_STRATEGY`, `CONTROL_PLANE_{ADDR,TOKEN,MAX_WORKERS}`, `WORKER_*`, `REDIS_*`, `RATE_LIMIT_*`, `POSTGRES_*`, `AUTH_*`, `EVENTS_*`, `TRACING_*`, `METRICS_*`, `LOG_LEVEL`); the mock worker takes flags (list-form `command:`); the admin tool reads `SERVERFLOW_POSTGRES_DSN`. `tests/deploy` (Go, no Docker, run in the `deploy` CI job and by `make quality`):

- `TestComposeStructure`: parses every compose file combination as YAML and asserts, per service, `read_only`, `cap_drop: [ALL]`, `no-new-privileges`, a healthcheck (or an explicit allow-list entry: the agent, one-shot jobs), `mem_limit`, a restart policy, a log-rotation option; every `ports` entry starts with `127.0.0.1:`; no `privileged`, `network_mode`, Docker socket, `container_name`; `depends_on` has a `condition` for every edge; every image is pinned `@sha256:`, not `:latest`, with an explicit non-`docker.io` host; no volume entry without a name or tmpfs; no `environment:` value that interpolates a secret variable (names matching `PASSWORD|TOKEN|SECRET|KEY|DSN`).
- `TestEnvVariablesAreHonoured`: for every `SERVERFLOW_*` key in the compose files, apply it (with its compose value) through `config`'s own overlay and fail if the configuration did not change (unless the value equals the default and is on a visible list); mock-worker `command:` lists are parsed with `mockworker.ParseFlags` and validated; unknown variables fail. This is the "every documented env var exists" test and also pins W1-W3.
- `TestPrometheusComposeMatchesLocal`, `TestTargetsMatchComposeServices` (every target host is a service, `worker_id` equals the agent's `SERVERFLOW_WORKER_ID`, metrics ports match the listen settings), `TestDockerfile` (literal pinned FROMs with digests, final stages non-root, `CGO_ENABLED=0`, one target per `cmd/` binary except `benchmark` and `healthcheck`, no `ADD`, no `ENV` of secret-looking names), `TestDockerignore`, `TestGitignoreCoversGeneratedFiles`, `TestMakefileTargets` (every command in D24 exists), `TestDevUpCheckEnv` (hostile `.env` files are rejected with the variable named and no value echoed), `TestNoSecretsCommitted` (no committed file under `deploy/`, compose, `.env.example` or docs contains a password-, token- or key-looking literal outside a marked allow-list).
- `cmd/healthcheck`: unit tests for loopback-only, timeout, non-2xx, redirect, and a non-HTTP port.

## Acceptance Criteria

1. **Clean checkout:** on a machine with only Docker (Compose 2.24+), `git`, `make`, `bash` and `curl`, `make dev-up` exits 0 and `make dev-smoke` exits 0 with the last line `smoke: N of N checks passed, 0 failed, 0 skipped` (all profiles); the verifier follows the README commands verbatim.
2. **Images:** every ServerFlow image runs as UID 65532 (`docker image inspect` `Config.User`), every container of the stack has `ReadonlyRootfs=true`, `CapDrop=[ALL]` and `no-new-privileges`, none is privileged, and no ServerFlow image contains a shell. A write to the root filesystem of the gateway container fails.
3. **Ports:** every published port of every container is bound to `127.0.0.1` (`docker compose ps --format json` and `docker port`); only gateway (or lb), control plane, Prometheus, Grafana and Jaeger UI publish anything; Postgres, Redis, Redpanda and every metrics listener are unreachable from the host (connection refused).
4. **Secrets:** a scan of the repository diff, `docker compose config --no-env-resolution`, `docker history --no-trunc` and a `docker save` of all six images, and the full `docker compose logs` finds none of the generated secret values (searched, not printed); the keys and tokens exist only under `.dev/` with modes 0600 (0644 only for `metrics_token`) and `.dev/` is ignored by git; no password literal is committed.
5. **No residue:** after `make dev-down` (default mode) `docker ps -a`, `docker volume ls` and `docker network ls` show no object of project `serverflow-dev` and the host's total volume count equals the count before `dev-up`; no container ever mounted an anonymous volume (mount inspection); `make dev-reset` additionally removes `.dev/` and the `serverflow/*:dev` images.
6. **Metrics listener:** the gateway and control plane started with `0.0.0.0` listeners and `SERVERFLOW_METRICS_TOKEN` return 401 without the bearer token and 200 with it from a peer container; Prometheus shows gateway, control plane and three mock workers `up`; with the token removed from the environment the binaries refuse to start (the guard is still on).
7. **Startup order:** with `postgres` made unhealthy, the gateway and consumer do not start and `dev-up` fails within the wait timeout naming the service; with `redpanda` stopped after start-up, requests still succeed (events are best-effort) and `dev-smoke` S9 reports the consumer lag honestly; a deliberately removed `depends_on` condition fails `TestComposeStructure`.
8. **Profiles:** `PROFILES=core make dev-up` and `make dev-smoke` succeed with auth, rate limit, events and tracing off, and the smoke lists every unavailable check as SKIPPED; `PROFILES=core,data` enables auth and rate limits; the full profile set and each documented subset pass `docker compose config`.
9. **Logs:** a failure of `dev-up` prints the failing service, its `ps` row and 20 log lines, and none of those lines contain a secret; CI artifact logs are secret-free (searched).
10. **Env surface:** every `SERVERFLOW_*` variable in the compose files changes the loaded configuration (`TestEnvVariablesAreHonoured`); W1-W3 each have tests for default refuse, explicit allow, and no secret in errors or logs.
11. **Collisions:** with ports 18080, 19090, 19091, 13000 and 16686 each occupied in turn by another listener, `dev-up` aborts before starting anything, names the variable to change, and starting again with that variable set works; two worktrees with different `COMPOSE_PROJECT_NAME` and ports run side by side.
12. **Hostile `.env`:** values containing `$`, quotes, spaces, newlines, `=`, `;`, backticks, a flag injection (`0.5 --failure-mode=drop`), out-of-range ports, duplicate ports, unknown profiles and an empty required value are all rejected before any container starts, with the variable named and the value not echoed.
13. **Failure injection:** `MOCK_3_FAILURE_RATE=1 MOCK_3_FAILURE_MODE=error` recreates only `mock-worker-3`, and the retry behaviour of ADR-012 is visible in `inference_attempts_total`; `docker compose kill mock-worker-3` removes it from the pool within the unhealthy timeout, requests continue to succeed (S11), and the container is not restarted automatically.
14. **Scale:** `GATEWAYS=3 make dev-up` starts three replicas behind the lb, Prometheus scrapes all three (`up` series with three instances), requests reach at least two replicas, and the `limited` tenant's quota is shared: the total admitted over the replicas stays within quota plus burst (S13); streaming works through the lb.
15. **Observability reuse:** `quality.sh observability` still passes unchanged for `prometheus.yml`; the Grafana dashboards load with zero provisioning errors in the Grafana log; the four dashboard panels fed by the compose stack show data after `dev-smoke` (screenshot or API evidence kept in the benchmark note).
16. **Images are pinned and non-Hub:** `docker compose config --images` lists only digest-pinned references with explicit non-`docker.io` hosts (`TestComposeStructure`); a build with Docker Hub unreachable (the daemon's access to `registry-1.docker.io` blocked in the verifier's check) still succeeds from a pre-pulled or mirror-served set.
17. **Reproducibility:** two `--no-cache` builds of the same commit produce identical SHA-256 for all six binaries; the stamped `serverflow_build_info{version,commit}` reports the build args (W2).

## Risks

- **Colima and Docker Desktop differ.** Only the home directory is mounted into containers (Colima), `host.docker.internal` exists on both but not on rootful Linux, bind-mount ownership and file modes differ (the `metrics_token` 0644 choice exists because of this), and Docker Desktop's file sharing may refuse 0600 sources for non-root container users. Mitigation: bind mounts only for read-only config and the token; everything writable is tmpfs or a named volume; the Colima note stays in the docs; Docker Desktop is listed as unverified.
- **Port collisions with other projects** (3000, 5433, 8000, 8900 on this machine). Mitigation: uncommon defaults, a pre-flight check naming the variable, and per-worktree project names. A collision at runtime between two Compose projects on the same image tag (`serverflow/gateway:dev`) is harmless (same build) but `dev-reset` removes the tag for both; documented.
- **Image pull limits and availability.** `mirror.gcr.io` and `public.ecr.aws` have unpublished anonymous limits (one 429 observed from ECR's token endpoint); `mirror.gcr.io` is a cache whose contents may lag or drop a tag. Digest pinning makes substitution impossible but not absence. Mitigation: retries with backoff, per-image overridable references, the Redpanda tarball cache kept in the integration job, the digest identical on Docker Hub as the last resort for local users who are logged in.
- **Disk.** Redpanda leaked 270 MB-1 GB per start once and filled the VM disk. Mitigation: tmpfs everywhere by default, explicit named volumes in persist mode, `docker rm -fv` semantics through `down -v`, the AC 5 leak check in CI, and a pre-flight warning when the engine reports under 5 GB free.
- **Memory on a 4 GB VM** shared with other stacks. Mitigation: limits (D8), idle numbers measured, `PROFILES` to run less; an OOM kill during the smoke would fail loudly (AC 20).
- **Compose version differences.** `required: false`, `--wait`, `--no-env-resolution`, `service_completed_successfully` and profiles behave differently in old versions. Mitigation: a minimum version check, the CI runner's version recorded, and structure tests that do not depend on rendering.
- **Security weakening is real and deliberate in W1:** a flag that allows the control-plane token over plain HTTP. It is off by default, named like its four siblings, and only the compose file sets it; the ADR says why, and the security review is a gate.
- **A shared metrics token and a world-readable `metrics_token` file** inside a private directory; acceptable for a throwaway local stack, documented as not a production pattern.
- **Smoke flakiness.** Time-based checks (scrape intervals of 15 s, heartbeat timeouts, consumer lag) are the usual source. Mitigation: every wait is a poll with a stated deadline, not a sleep; the nightly run repeats it; a flake is a bug in the check, not a retry.
- **Classic-builder slowness and deprecation.** 42 s warm rebuilds and a deprecation banner; a future Docker release may remove the classic builder. Mitigation: the Dockerfile is BuildKit-compatible, so installing buildx is a one-line documented step.
- **Scope creep toward Phase 15/17.** The failover check (S11) and the lb touch chaos and Kubernetes ground; both stay minimal and are named in the PR.
- **The skeleton's deletion removes a file other docs mention.** Mitigation: a grep for `docker-compose.yml` and `otel-collector` references is an implementation step and a review item.
